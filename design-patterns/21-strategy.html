Strategy Pattern

Định nghĩa họ các thuật toán, đóng gói mỗi thuật toán và làm chúng hoán đổi được

Nguồn: Design Patterns — Behavioral Pattern
Tư duy cốt lõi Đóng gói thuật toán vào class riêng để có thể swap runtime. Client chọn strategy phù hợp mà không cần biết implementation details. Giống như GPS navigation — cùng đích đến nhưng chọn route: nhanh nhất, ngắn nhất, tránh toll.

Cấu trúc

Context → Strategy interface → ConcreteStrategy A/B/C

Thành phầnVai trò
StrategyInterface định nghĩa algorithm method
ConcreteStrategyImplement algorithm cụ thể
ContextGiữ reference đến Strategy, delegate work

Triển khai

Ví dụ: Payment Processing

// Strategy interface
interface PaymentStrategy {
    void pay(int amount);
}

// ConcreteStrategy: Credit Card
class CreditCardPayment implements PaymentStrategy {
    private String cardNumber;

    public CreditCardPayment(String cardNumber) {
        this.cardNumber = cardNumber;
    }

    public void pay(int amount) {
        System.out.println("Paid $" + amount + " via Credit Card " +
            cardNumber.substring(cardNumber.length() - 4));
    }
}

// ConcreteStrategy: PayPal
class PayPalPayment implements PaymentStrategy {
    private String email;

    public PayPalPayment(String email) {
        this.email = email;
    }

    public void pay(int amount) {
        System.out.println("Paid $" + amount + " via PayPal: " + email);
    }
}

// ConcreteStrategy: Crypto
class CryptoPayment implements PaymentStrategy {
    private String walletAddress;

    public CryptoPayment(String walletAddress) {
        this.walletAddress = walletAddress;
    }

    public void pay(int amount) {
        System.out.println("Paid $" + amount + " via Crypto to " +
            walletAddress.substring(0, 8) + "...");
    }
}

// Context
class ShoppingCart {
    private PaymentStrategy paymentStrategy;

    public void setPaymentStrategy(PaymentStrategy strategy) {
        this.paymentStrategy = strategy;
    }

    public void checkout(int amount) {
        paymentStrategy.pay(amount);
    }
}

Sử dụng

ShoppingCart cart = new ShoppingCart();

// Pay with Credit Card
cart.setPaymentStrategy(new CreditCardPayment("1234567890123456"));
cart.checkout(100);  // Paid $100 via Credit Card 3456

// Pay with PayPal
cart.setPaymentStrategy(new PayPalPayment("user@example.com"));
cart.checkout(200);  // Paid $200 via PayPal: user@example.com

// Pay with Crypto
cart.setPaymentStrategy(new CryptoPayment("0x1234abcd5678efgh"));
cart.checkout(300);  // Paid $300 via Crypto to 0x1234ab...

Ưu điểm & Nhược điểm

Ưu điểm

  • Open/Closed: thêm strategy mới không sửa code cũ
  • Loại bỏ conditional statements
  • Swap algorithms runtime
  • Dễ unit test từng strategy riêng biệt

Nhược điểm

  • Client phải biết các strategies để chọn đúng
  • Tăng số lượng objects
  • Overkill nếu chỉ có vài algorithms đơn giản

Khi nào nên dùng

Dùng Strategy khi
  • Nhiều algorithms cho cùng task: Sorting, compression, validation
  • Cần swap runtime: User chọn method khác nhau
  • Tránh conditional explosion: Nhiều if/switch cho variants
  • Isolate algorithm logic: Dễ test, dễ maintain
  • Ví dụ thực tế: Payment methods, sorting algorithms, compression formats, authentication strategies, routing algorithms, pricing strategies
