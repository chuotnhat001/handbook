Factory Method Pattern

Định nghĩa interface tạo object, để subclass quyết định class nào được khởi tạo

Nguồn: Design Patterns — Creational Pattern
Tư duy cốt lõi Thay vì gọi trực tiếp new ConcreteProduct(), client gọi qua một phương thức trừu tượng — các lớp con quyết định lớp nào sẽ được khởi tạo. Tách biệt logic khởi tạo khỏi business logic.

Cấu trúc

Bốn thành phần chính:

Thành phầnVai trò
ProductInterface/Abstract Class định nghĩa giao diện chung cho tất cả sản phẩm
ConcreteProductCác lớp cụ thể triển khai Product interface
CreatorChứa phương thức factory trừu tượng factoryMethod()
ConcreteCreatorGhi đè factory method để trả về ConcreteProduct cụ thể

Luồng hoạt động:

Client → ConcreteCreator.factoryMethod() → ConcreteProduct
Client chỉ biết Creator và Product interface, không biết lớp cụ thể

Triển khai

Ví dụ cơ bản

// 1. Product Interface
interface Product {
    void doSomething();
}

// 2. Concrete Products
class ProductA implements Product {
    @Override
    public void doSomething() {
        System.out.println("ProductA is doing something.");
    }
}

class ProductB implements Product {
    @Override
    public void doSomething() {
        System.out.println("ProductB is doing something.");
    }
}

// 3. Creator (Abstract)
abstract class Creator {
    public abstract Product factoryMethod();

    public void anOperation() {
        Product product = factoryMethod();
        product.doSomething();
    }
}

// 4. Concrete Creators
class ConcreteCreatorA extends Creator {
    @Override
    public Product factoryMethod() {
        return new ProductA();
    }
}

class ConcreteCreatorB extends Creator {
    @Override
    public Product factoryMethod() {
        return new ProductB();
    }
}

Sử dụng

public class Main {
    public static void main(String[] args) {
        Creator creatorA = new ConcreteCreatorA();
        creatorA.anOperation(); // ProductA is doing something.

        Creator creatorB = new ConcreteCreatorB();
        creatorB.anOperation(); // ProductB is doing something.
    }
}

Ưu điểm & Nhược điểm

Ưu điểm

  • Tách biệt quá trình khởi tạo khỏi business logic — client không phụ thuộc vào lớp cụ thể
  • Dễ mở rộng: thêm loại sản phẩm mới chỉ cần thêm ConcreteProduct + ConcreteCreator
  • Tuân thủ Single Responsibility Principle: logic tạo đối tượng nằm ở một chỗ
  • Tuân thủ Open/Closed Principle: mở với mở rộng, đóng với sửa đổi

Nhược điểm

  • Tăng số lượng class: mỗi ConcreteProduct cần một ConcreteCreator tương ứng
  • Có thể quá phức tạp (over-engineering) cho bài toán đơn giản
  • Yêu cầu tất cả sản phẩm phải có interface hoặc base class chung

Khi nào nên dùng

Dùng Factory Method khi
  • Không biết trước chính xác kiểu đối tượng nào sẽ cần tạo
  • Muốn cho phép người dùng thư viện/framework mở rộng các thành phần
  • Cần tái sử dụng các đối tượng (object pool, cache)
  • Logic khởi tạo phức tạp, có nhiều bước hoặc phụ thuộc điều kiện
Không nên dùng khi Chỉ có một loại sản phẩm duy nhất, không có kế hoạch mở rộng. Logic khởi tạo đơn giản — new ConcreteProduct() đã đủ.

Ví dụ thực tế

Hệ thống thanh toán e-commerce

Thay vì hardcode logic COD, thẻ tín dụng, ví điện tử vào cùng một chỗ:

// Product Interface
interface PaymentMethod {
    void processPayment(double amount);
}

// Concrete Products
class CashOnDelivery implements PaymentMethod {
    @Override
    public void processPayment(double amount) {
        System.out.println("COD: Thu " + amount + " khi giao hàng");
    }
}

class MoMoPayment implements PaymentMethod {
    @Override
    public void processPayment(double amount) {
        System.out.println("MoMo: Chuyển " + amount + " qua ví điện tử");
    }
}

// Abstract Creator
abstract class PaymentFactory {
    public abstract PaymentMethod createPayment();
}

// Concrete Creators
class CODFactory extends PaymentFactory {
    @Override
    public PaymentMethod createPayment() {
        return new CashOnDelivery();
    }
}

class MoMoFactory extends PaymentFactory {
    @Override
    public PaymentMethod createPayment() {
        return new MoMoPayment();
    }
}

Lợi ích: Khi thêm ZaloPay — chỉ thêm ZaloPayment + ZaloPayFactory, không đụng vào code xử lý đơn hàng.
