Observer Pattern

Định nghĩa quan hệ một-nhiều, khi một object thay đổi thì các object phụ thuộc được thông báo

Nguồn: Design Patterns — Behavioral Pattern
Tư duy cốt lõi Subject (publisher) giữ danh sách observers (subscribers) và notify tất cả khi state thay đổi. Giống như YouTube subscription — bạn subscribe channel, channel notify khi có video mới, không cần bạn polling.

Cấu trúc

Subject → Observer interface ← ConcreteObserver

Thành phầnVai trò
SubjectGiữ list observers, methods: attach(), detach(), notify()
ObserverInterface định nghĩa update() method
ConcreteSubjectGiữ state, gọi notify() khi state thay đổi
ConcreteObserverImplement update(), react to subject changes

Triển khai

Ví dụ: Stock Price Notification

// Observer interface
interface StockObserver {
    void update(String stockSymbol, double price);
}

// Subject
class StockMarket {
    private List<StockObserver> observers = new ArrayList<>();
    private Map<String, Double> prices = new HashMap<>();

    public void attach(StockObserver observer) {
        observers.add(observer);
    }

    public void detach(StockObserver observer) {
        observers.remove(observer);
    }

    public void setPrice(String symbol, double price) {
        prices.put(symbol, price);
        notifyObservers(symbol, price);
    }

    private void notifyObservers(String symbol, double price) {
        for (StockObserver observer : observers) {
            observer.update(symbol, price);
        }
    }
}

// ConcreteObserver: Mobile App
class MobileApp implements StockObserver {
    private String name;

    public MobileApp(String name) { this.name = name; }

    public void update(String symbol, double price) {
        System.out.println(name + " received: " + symbol + " = $" + price);
    }
}

// ConcreteObserver: Trading Bot
class TradingBot implements StockObserver {
    public void update(String symbol, double price) {
        if (price < 100) {
            System.out.println("Bot: BUY " + symbol + " at $" + price);
        }
    }
}

Sử dụng

StockMarket market = new StockMarket();

StockObserver app1 = new MobileApp("Alice's Phone");
StockObserver app2 = new MobileApp("Bob's Phone");
StockObserver bot = new TradingBot();

market.attach(app1);
market.attach(app2);
market.attach(bot);

market.setPrice("AAPL", 150.0);
// Alice's Phone received: AAPL = $150.0
// Bob's Phone received: AAPL = $150.0

market.setPrice("GOOG", 95.0);
// Alice's Phone received: GOOG = $95.0
// Bob's Phone received: GOOG = $95.0
// Bot: BUY GOOG at $95.0

Ưu điểm & Nhược điểm

Ưu điểm

  • Open/Closed: thêm observer mới không sửa subject
  • Loose coupling giữa subject và observers
  • Hỗ trợ broadcast communication
  • Có thể thêm/bớt observers runtime

Nhược điểm

  • Observers được notify theo thứ tự không xác định
  • Memory leaks nếu quên detach observers
  • Cascading updates có thể khó debug
  • Update overhead nếu có quá nhiều observers

Khi nào nên dùng

Dùng Observer khi
  • One-to-many dependency: Nhiều objects cần react khi một object thay đổi
  • Không biết trước số lượng observers: Dynamic subscription
  • Loose coupling: Subject không cần biết observers cụ thể
  • Event-driven systems: GUI events, pub/sub messaging
  • Ví dụ thực tế: Event listeners, MVC (Model notifies Views), React state, RxJS, message queues, webhooks
