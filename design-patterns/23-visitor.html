Visitor Pattern

Thêm operations mới cho các class mà không thay đổi chúng, tách thuật toán khỏi cấu trúc

Nguồn: Design Patterns — Behavioral Pattern
Tư duy cốt lõi Tách operation khỏi object structure — operations được định nghĩa trong visitor classes riêng biệt. Dùng double dispatch: element gọi visitor.visit(this), visitor biết chính xác type để xử lý. Thêm operation mới = thêm visitor mới, không sửa element classes.

Cấu trúc

Element.accept(Visitor) → Visitor.visit(ConcreteElement)

Thành phầnVai trò
VisitorInterface với visit() method cho mỗi ConcreteElement type
ConcreteVisitorImplement operation cụ thể cho mỗi element type
ElementInterface định nghĩa accept(Visitor)
ConcreteElementImplement accept() gọi visitor.visit(this)
ObjectStructureCollection chứa elements, có thể iterate và accept visitor

Triển khai

Ví dụ: Document Export

// Element interface
interface DocumentPart {
    void accept(DocumentVisitor visitor);
}

// ConcreteElements
class Paragraph implements DocumentPart {
    private String text;

    public Paragraph(String text) { this.text = text; }
    public String getText() { return text; }

    public void accept(DocumentVisitor visitor) {
        visitor.visit(this);
    }
}

class Image implements DocumentPart {
    private String url;

    public Image(String url) { this.url = url; }
    public String getUrl() { return url; }

    public void accept(DocumentVisitor visitor) {
        visitor.visit(this);
    }
}

class Table implements DocumentPart {
    private String[][] data;

    public Table(String[][] data) { this.data = data; }
    public String[][] getData() { return data; }

    public void accept(DocumentVisitor visitor) {
        visitor.visit(this);
    }
}

// Visitor interface
interface DocumentVisitor {
    void visit(Paragraph p);
    void visit(Image img);
    void visit(Table t);
}

// ConcreteVisitor: HTML Export
class HTMLExportVisitor implements DocumentVisitor {
    private StringBuilder html = new StringBuilder();

    public void visit(Paragraph p) {
        html.append("<p>").append(p.getText()).append("</p>\n");
    }

    public void visit(Image img) {
        html.append("<img src=\"").append(img.getUrl()).append("\">\n");
    }

    public void visit(Table t) {
        html.append("<table>\n");
        for (String[] row : t.getData()) {
            html.append("  <tr>");
            for (String cell : row) {
                html.append("<td>").append(cell).append("</td>");
            }
            html.append("</tr>\n");
        }
        html.append("</table>\n");
    }

    public String getHTML() { return html.toString(); }
}

// ConcreteVisitor: Plain Text Export
class PlainTextVisitor implements DocumentVisitor {
    private StringBuilder text = new StringBuilder();

    public void visit(Paragraph p) {
        text.append(p.getText()).append("\n\n");
    }

    public void visit(Image img) {
        text.append("[Image: ").append(img.getUrl()).append("]\n\n");
    }

    public void visit(Table t) {
        for (String[] row : t.getData()) {
            text.append(String.join(" | ", row)).append("\n");
        }
        text.append("\n");
    }

    public String getText() { return text.toString(); }
}

Sử dụng

List<DocumentPart> document = Arrays.asList(
    new Paragraph("Hello World"),
    new Image("photo.jpg"),
    new Table(new String[][] {{"A", "B"}, {"1", "2"}})
);

// Export to HTML
HTMLExportVisitor htmlVisitor = new HTMLExportVisitor();
for (DocumentPart part : document) {
    part.accept(htmlVisitor);
}
System.out.println(htmlVisitor.getHTML());
// <p>Hello World</p>
// <img src="photo.jpg">
// <table>...

// Export to Plain Text
PlainTextVisitor textVisitor = new PlainTextVisitor();
for (DocumentPart part : document) {
    part.accept(textVisitor);
}
System.out.println(textVisitor.getText());
// Hello World
// [Image: photo.jpg]
// A | B
// 1 | 2

Ưu điểm & Nhược điểm

Ưu điểm

  • Open/Closed cho operations: thêm visitor mới không sửa elements
  • Single Responsibility: mỗi visitor chứa một operation
  • Accumulating state: visitor có thể tích lũy data khi traverse

Nhược điểm

  • Closed cho elements: thêm element type phải sửa TẤT CẢ visitors
  • Có thể break encapsulation nếu visitor cần access private state
  • Complexity cao, double dispatch khó hiểu

Khi nào nên dùng

Dùng Visitor khi
  • Element hierarchy ổn định: Ít thay đổi element types
  • Nhiều operations khác nhau: Cần thêm operations thường xuyên
  • Tách concerns: Operations không thuộc về elements
  • Ví dụ thực tế: Compiler AST (type checking, code generation, optimization), document processing (export to HTML/PDF/Word), tax calculation on shopping cart items, file system operations
