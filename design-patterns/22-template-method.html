Template Method Pattern

Định nghĩa khung thuật toán, cho phép subclass override các bước cụ thể

Nguồn: Design Patterns — Behavioral Pattern
Tư duy cốt lõi Base class định nghĩa skeleton của algorithm với các bước cố định + các bước có thể override. Subclass customize các bước cụ thể mà không thay đổi structure chung. Giống như recipe — quy trình nấu cơ bản giống nhau, nhưng gia vị có thể thay đổi.

Cấu trúc

AbstractClass (templateMethod + primitiveOperations) → ConcreteClass

Thành phầnVai trò
AbstractClassĐịnh nghĩa templateMethod() (final) gọi các primitive operations
Primitive OperationsAbstract methods cho subclass implement
Hook OperationsOptional methods với default implementation
ConcreteClassOverride primitive operations để customize behavior

Triển khai

Ví dụ: Data Mining Pipeline

// AbstractClass
abstract class DataMiner {
    // Template method — final, cannot be overridden
    public final void mine(String path) {
        openFile(path);
        extractData();
        parseData();
        analyzeData();
        sendReport();
        closeFile();
    }

    // Primitive operations — MUST be implemented
    abstract void openFile(String path);
    abstract void extractData();
    abstract void closeFile();

    // Common operations — shared implementation
    void parseData() {
        System.out.println("Parsing data into common format...");
    }

    void analyzeData() {
        System.out.println("Analyzing data...");
    }

    // Hook — optional, can be overridden
    void sendReport() {
        System.out.println("Sending generic report...");
    }
}

// ConcreteClass: PDF Miner
class PDFMiner extends DataMiner {
    void openFile(String path) {
        System.out.println("Opening PDF: " + path);
    }

    void extractData() {
        System.out.println("Extracting text from PDF pages...");
    }

    void closeFile() {
        System.out.println("Closing PDF reader");
    }
}

// ConcreteClass: CSV Miner
class CSVMiner extends DataMiner {
    void openFile(String path) {
        System.out.println("Opening CSV: " + path);
    }

    void extractData() {
        System.out.println("Reading CSV rows...");
    }

    void closeFile() {
        System.out.println("Closing CSV stream");
    }

    // Override hook
    @Override
    void sendReport() {
        System.out.println("Sending CSV-specific Excel report...");
    }
}

Sử dụng

DataMiner pdfMiner = new PDFMiner();
pdfMiner.mine("report.pdf");
// Opening PDF: report.pdf
// Extracting text from PDF pages...
// Parsing data into common format...
// Analyzing data...
// Sending generic report...
// Closing PDF reader

DataMiner csvMiner = new CSVMiner();
csvMiner.mine("data.csv");
// Opening CSV: data.csv
// Reading CSV rows...
// Parsing data into common format...
// Analyzing data...
// Sending CSV-specific Excel report...
// Closing CSV stream

Ưu điểm & Nhược điểm

Ưu điểm

  • Code reuse: common logic trong base class
  • Inversion of Control: base class gọi subclass methods
  • Open/Closed: thêm variant mới không sửa base
  • Enforces structure: subclass phải tuân theo skeleton

Nhược điểm

  • Hạn chế flexibility: subclass bị ràng buộc bởi skeleton
  • Có thể vi phạm Liskov Substitution nếu subclass làm rỗng steps
  • Khó hiểu flow khi có nhiều hooks

Khi nào nên dùng

Dùng Template Method khi
  • Algorithm có structure chung: Các bước giống nhau, chỉ khác implementation
  • Muốn enforce invariants: Một số bước PHẢI chạy theo thứ tự
  • Code duplication: Nhiều class có cùng skeleton algorithm
  • Hook points: Cho phép extension ở những điểm xác định
  • Ví dụ thực tế: Unit test frameworks (setUp/test/tearDown), build tools, data parsers, game loops, HTTP request handling
