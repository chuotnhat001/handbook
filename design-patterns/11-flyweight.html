Flyweight Pattern

Chia sẻ dữ liệu chung giữa nhiều object để tiết kiệm bộ nhớ

Nguồn: Design Patterns — Structural Pattern
Tư duy cốt lõi Flyweight chia sẻ intrinsic state (trạng thái chung, không đổi) giữa nhiều object. Extrinsic state (trạng thái riêng, thay đổi) do Client giữ và truyền vào khi cần.

Cấu trúc

Thành phầnVai trò
FlyweightChứa intrinsic state (trạng thái chung, được chia sẻ)
FlyweightFactoryTạo, quản lý và cấp phát các Flyweight, đảm bảo tái sử dụng
ClientGiữ extrinsic state (trạng thái riêng), truyền vào khi cần

Triển khai

Ví dụ: Game với hàng ngàn cây

// Flyweight — chứa intrinsic state (name, color, texture)
class TreeType {
    private final String name, color, texture;

    public TreeType(String name, String color, String texture) {
        this.name = name;
        this.color = color;
        this.texture = texture;
    }

    public void draw(int x, int y) {
        System.out.println("Drawing " + name + " at (" + x + ", " + y + ")");
    }
}

// FlyweightFactory
class TreeFactory {
    private static Map<String, TreeType> types = new HashMap<>();

    public static TreeType getTreeType(String name, String color, String texture) {
        TreeType result = types.get(name);
        if (result == null) {
            result = new TreeType(name, color, texture);
            types.put(name, result);
        }
        return result;
    }
}

// Client — chứa extrinsic state (x, y)
class Tree {
    private final int x, y;
    private final TreeType treeType;

    public Tree(int x, int y, TreeType treeType) {
        this.x = x; this.y = y; this.treeType = treeType;
    }

    public void draw() {
        treeType.draw(x, y);
    }
}

Ưu điểm & Nhược điểm

Ưu điểm

  • Giảm đáng kể lượng bộ nhớ tiêu thụ
  • Tăng hiệu suất nhờ tái sử dụng đối tượng
  • Phù hợp cho ứng dụng đồ họa, trò chơi, hệ thống mạng

Nhược điểm

  • Tăng độ phức tạp mã nguồn do phải quản lý qua Factory
  • Khó phân biệt trạng thái nội/ngoại tại trong một số trường hợp
  • Có thể gây synchronization issues trong môi trường multi-threaded

Khi nào nên dùng

Dùng Flyweight khi
  • Cần xử lý hàng ngàn/triệu đối tượng với trạng thái tương tự
  • Có thể phân biệt rõ intrinsic (chung) vs extrinsic (riêng)
  • Tiết kiệm bộ nhớ và hiệu suất là ưu tiên chính
