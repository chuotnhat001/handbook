Chain of Responsibility Pattern

Chuyển request dọc theo chuỗi handler, mỗi handler quyết định xử lý hoặc chuyển tiếp

Nguồn: Design Patterns — Behavioral Pattern
Tư duy cốt lõi Tách sender và receiver — sender không cần biết handler nào sẽ xử lý request. Các handler được nối thành chuỗi, mỗi handler tự quyết định: xử lý request hoặc chuyển cho handler tiếp theo.

Cấu trúc

Client → Handler1 → Handler2 → Handler3 → ...

Thành phầnVai trò
HandlerInterface định nghĩa method xử lý và reference đến handler tiếp theo
BaseHandlerAbstract class implement logic chuyển tiếp mặc định
ConcreteHandlerXử lý request cụ thể hoặc chuyển tiếp
ClientGửi request vào đầu chuỗi

Triển khai

Ví dụ: Hệ thống phê duyệt chi tiêu

// Handler interface
abstract class Approver {
    protected Approver nextApprover;

    public void setNext(Approver next) {
        this.nextApprover = next;
    }

    public abstract void approve(int amount);
}

// ConcreteHandler: Team Lead - duyệt đến 1000
class TeamLead extends Approver {
    public void approve(int amount) {
        if (amount <= 1000) {
            System.out.println("Team Lead approved $" + amount);
        } else if (nextApprover != null) {
            nextApprover.approve(amount);
        }
    }
}

// ConcreteHandler: Manager - duyệt đến 5000
class Manager extends Approver {
    public void approve(int amount) {
        if (amount <= 5000) {
            System.out.println("Manager approved $" + amount);
        } else if (nextApprover != null) {
            nextApprover.approve(amount);
        }
    }
}

// ConcreteHandler: Director - duyệt đến 10000
class Director extends Approver {
    public void approve(int amount) {
        if (amount <= 10000) {
            System.out.println("Director approved $" + amount);
        } else {
            System.out.println("Amount $" + amount + " requires CEO approval");
        }
    }
}

Sử dụng

// Xây dựng chuỗi
Approver teamLead = new TeamLead();
Approver manager = new Manager();
Approver director = new Director();

teamLead.setNext(manager);
manager.setNext(director);

// Gửi request
teamLead.approve(500);   // Team Lead approved $500
teamLead.approve(3000);  // Manager approved $3000
teamLead.approve(8000);  // Director approved $8000
teamLead.approve(15000); // Amount $15000 requires CEO approval

Ưu điểm & Nhược điểm

Ưu điểm

  • Giảm coupling giữa sender và receiver
  • Single Responsibility: mỗi handler chỉ lo việc của mình
  • Open/Closed: thêm handler mới không ảnh hưởng code cũ
  • Linh hoạt thay đổi thứ tự hoặc thành phần chuỗi runtime

Nhược điểm

  • Request có thể không được xử lý nếu chuỗi không có handler phù hợp
  • Khó debug vì request đi qua nhiều handler
  • Có thể ảnh hưởng performance nếu chuỗi quá dài

Khi nào nên dùng

Dùng Chain of Responsibility khi
  • Nhiều handler có thể xử lý: Không biết trước handler nào sẽ xử lý
  • Xử lý theo thứ tự: Request phải qua các bước kiểm tra tuần tự
  • Tập handler thay đổi runtime: Cần thêm/bớt handler linh hoạt
  • Middleware pipeline: HTTP request filters, logging chains
  • Event bubbling: DOM events, GUI event handling
