Bridge Pattern

Tách abstraction khỏi implementation để cả hai có thể thay đổi độc lập

Nguồn: Design Patterns — Structural Pattern
Tư duy cốt lõi Bridge giải quyết vấn đề class explosion khi kết hợp nhiều biến thể. Thay vì N×M lớp con, chỉ cần N + M lớp. Abstraction giữ reference đến Implementor (composition thay vì inheritance).

Cấu trúc

Thành phầnVai trò
AbstractionLớp cơ sở, quản lý công việc qua tham chiếu đến Implementor
RefinedAbstractionLớp con mở rộng Abstraction
ImplementorInterface định nghĩa các tác vụ cần thiết
ConcreteImplementorLớp chứa logic cụ thể

Triển khai

Ví dụ: Shape × Color

// Implementor
public interface Color {
    void applyColor();
}

// ConcreteImplementors
public class RedColor implements Color {
    public void applyColor() {
        System.out.println("Red color.");
    }
}

public class BlueColor implements Color {
    public void applyColor() {
        System.out.println("Blue color.");
    }
}

// Abstraction
public abstract class Shape {
    protected Color color;  // Bridge — composition

    public Shape(Color color) {
        this.color = color;
    }
    public abstract void draw();
}

// RefinedAbstraction
public class Circle extends Shape {
    public Circle(Color color) { super(color); }

    @Override
    public void draw() {
        System.out.print("Draw Circle in ");
        color.applyColor();
    }
}

public class Square extends Shape {
    public Square(Color color) { super(color); }

    @Override
    public void draw() {
        System.out.print("Draw Square in ");
        color.applyColor();
    }
}

Sử dụng

Shape redCircle = new Circle(new RedColor());
Shape blueSquare = new Square(new BlueColor());

redCircle.draw();   // Draw Circle in Red color.
blueSquare.draw();  // Draw Square in Blue color.

Ưu điểm & Nhược điểm

Ưu điểm

  • Tách rời hoàn toàn: Abstraction và Implementation thay đổi độc lập
  • Giảm class explosion: Thay vì N×M lớp con, chỉ cần N + M lớp
  • Open/Closed Principle: Thêm abstraction hoặc implementation mới không sửa code cũ
  • Linh hoạt runtime: Có thể swap implementation trong lúc chạy

Nhược điểm

  • Tăng số lượng lớp/interface
  • Khó đọc hơn cho người mới
  • Over-engineering nếu chỉ có 1-2 tổ hợp

Khi nào nên dùng

Dùng Bridge khi
  • Hệ thống có hai chiều biến thể độc lập (hình dạng × màu sắc, ngân hàng × loại tài khoản)
  • Muốn tránh class explosion khi dùng kế thừa đa tầng
  • Implementation cần thay đổi tại runtime
  • Muốn chia sẻ một implementation giữa nhiều object
