Prototype Pattern

Tạo object mới bằng cách sao chép một prototype có sẵn thay vì khởi tạo từ đầu

Nguồn: Design Patterns — Creational Pattern
Tư duy cốt lõi Prototype không tạo đối tượng từ đầu — nó sao chép (clone) từ đối tượng đã tồn tại. Đối tượng tự biết cách nhân bản chính nó, client không cần biết class cụ thể.

Cấu trúc

Thành phầnVai trò
PrototypeInterface khai báo phương thức clone()
ConcretePrototypeTriển khai clone(), tự sao chép chính mình
ClientGọi clone() thay vì dùng new

Quan hệ: Client → Prototype (interface) ← ConcretePrototype

Triển khai

Interface Prototype

public interface CloneableShape extends Cloneable {
    CloneableShape clone();
    void draw();
}

Concrete Prototypes

public class Circle implements CloneableShape {
    private int radius;

    public Circle(int radius) {
        this.radius = radius;
    }

    @Override
    public CloneableShape clone() {
        return new Circle(this.radius);
    }

    @Override
    public void draw() {
        System.out.println("Drawing circle, radius: " + radius);
    }
}

public class Rectangle implements CloneableShape {
    private int width, height;

    public Rectangle(int width, int height) {
        this.width = width;
        this.height = height;
    }

    @Override
    public CloneableShape clone() {
        return new Rectangle(this.width, this.height);
    }

    @Override
    public void draw() {
        System.out.println("Drawing rectangle: " + width + "x" + height);
    }
}

Sử dụng

Circle original = new Circle(10);
Circle cloned = (Circle) original.clone();

original.draw(); // Drawing circle, radius: 10
cloned.draw();   // Drawing circle, radius: 10

// Hai đối tượng độc lập, thay đổi 1 không ảnh hưởng cái kia

Prototype Registry (nâng cao)

Lưu trữ các prototype sẵn có để tái sử dụng:

public class ShapeRegistry {
    private Map<String, CloneableShape> registry = new HashMap<>();

    public void register(String key, CloneableShape shape) {
        registry.put(key, shape);
    }

    public CloneableShape get(String key) {
        return registry.get(key).clone();
    }
}

Ưu điểm & Nhược điểm

Ưu điểm

  • Hiệu suất cao: Sao chép nhanh hơn khởi tạo từ đầu với đối tượng phức tạp
  • Đơn giản hóa client: Client không cần biết class cụ thể
  • Linh hoạt: Có thể thêm/xóa prototype lúc runtime
  • Tránh subclass bùng nổ: Không cần tạo nhiều subclass factory

Nhược điểm

  • Deep copy phức tạp: Khi đối tượng chứa tham chiếu lồng nhau hoặc vòng tròn
  • Clone ẩn: Không rõ ràng là shallow hay deep copy, dễ gây bug
  • Overhead không cần thiết: Nếu đối tượng nhẹ, tạo mới bằng new đơn giản hơn

Khi nào nên dùng

Dùng Prototype khi
  • Khởi tạo đối tượng tốn kém (kết nối database, đọc file, gọi network)
  • Cần tạo nhiều bản sao với trạng thái gần giống nhau
  • Class cụ thể không biết trước tại compile time
  • Muốn tránh class hierarchy phức tạp của các factory
  • Cần lưu trữ snapshot trạng thái đối tượng (kết hợp Memento)

Ví dụ thực tế

DomainPrototype usage
