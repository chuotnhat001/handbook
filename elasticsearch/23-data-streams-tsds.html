Data Streams & TSDS

Data stream, naming scheme, TSDS, dimension và metric, downsampling, synthetic _source

Nguồn: Elastic — Data Streams, Elastic — Time Series Data Stream

Mục Tiêu Học Tập

Sau khi hoàn thành bài này, bạn sẽ: Hiểu data stream gồm những gì và khác index alias ra sao. Đặt tên data stream theo naming scheme của Elastic. Thao tác với data stream: ghi, rollover, cập nhật mapping, sửa và xóa document. Cấu hình retention bằng data stream lifecycle. Dùng Time Series Data Stream (TSDS) với dimension và metric, giảm dung lượng bằng downsampling và synthetic _source.

Data Stream Là Gì

Data stream là một tên logic dùng để ghi và đọc dữ liệu time-series append-only. Phía sau là một chuỗi backing index ẩn, mỗi lần rollover sinh thêm một backing index mới.

logs-app-default → .ds-logs-app-default-2026.10.01-000001 → ...-000002 → ...-000003 (write index)
  • Ghi luôn đi vào backing index mới nhất (write index)
  • Đọc trải trên mọi backing index
  • Bắt buộc có field @timestamp kiểu date hoặc date_nanos
  • Chỉ cho phép op_type=create: không index đè document cùng _id qua tên data stream
  • Được tạo từ index template có khối "data_stream": {}
Data streamIndex alias + rollover
Thiết lậpChỉ cần index template, tự tạo khi ghi lần đầuTemplate + bootstrap index + rollover_alias
Ghi đè theo IDKhông (phải nhắm vào backing index)Có
@timestampBắt buộcKhông bắt buộc
Phù hợpLog, metric, event, traceDữ liệu có thời gian nhưng cần cập nhật thường xuyên
Tư duy cốt lõi Data stream mã hóa một giả định vào hệ thống: dữ liệu này chỉ thêm mới, không sửa. Khi giả định đúng (log, metric), Elasticsearch có thể tự quản lý rollover, retention và tối ưu lưu trữ thay bạn.

Naming Scheme

Elastic Agent, Fleet integrations và nhiều Beats dùng quy ước đặt tên:

<type>-<dataset>-<namespace>

logs-nginx.access-production
metrics-system.cpu-default
traces-apm-default
synthetics-http-staging
PhầnÝ nghĩaVí dụ
typeLoại dữ liệulogs, metrics, traces, synthetics
datasetNguồn và cấu trúc dữ liệunginx.access, orders.app
namespaceNhóm do người dùng định nghĩaproduction, staging, team-payments

Lợi ích của quy ước này:

  • Elasticsearch có sẵn index template cho logs-*-* và metrics-*-* (mapping theo ECS, lifecycle mặc định)
  • Phân quyền theo namespace: role đọc logs-*-team-payments chỉ thấy log của team Payments
  • Retention khác nhau theo namespace: production giữ 90 ngày, staging giữ 7 ngày
Dấu gạch ngang trong dataset Dataset và namespace không được chứa dấu - vì nó là ký tự phân cách. Dùng dấu chấm (orders.app) hoặc gạch dưới. Tên data stream cũng phải viết thường.

Thao Tác Với Data Stream

Tạo template và ghi

PUT /_index_template/logs-orders
{
  "index_patterns": ["logs-orders.app-*"],
  "data_stream": {},
  "priority": 200,
  "composed_of": ["logs@mappings", "logs@settings"],
  "template": {
    "mappings": { "properties": {
      "order.id":    { "type": "keyword" },
      "order.total": { "type": "scaled_float", "scaling_factor": 100 }
    } }
  }
}

POST /logs-orders.app-default/_doc
{ "@timestamp": "2026-10-28T08:00:00Z", "message": "order created", "order": { "id": "ORD-1", "total": 120 } }

GET /_data_stream/logs-orders.app-default

priority cao hơn template có sẵn logs (priority 100) để template của bạn được chọn. Component template logs@mappings, logs@settings có sẵn từ ES 8.x, giúp kế thừa cấu hình chuẩn.

Rollover và cập nhật mapping

# Rollover thủ công (bình thường do ILM hoặc lifecycle làm)
POST /logs-orders.app-default/_rollover

# Thêm field mới: sửa template, rồi cập nhật mapping của write index hiện tại
PUT /_index_template/logs-orders  ...  (thêm field customer.tier)
PUT /logs-orders.app-default/_mapping
{ "properties": { "customer.tier": { "type": "keyword" } } }

# Đổi type của field có sẵn: chỉ áp dụng cho backing index mới.
# Sửa template, rồi rollover. Backing index cũ giữ mapping cũ.

Sửa và xóa document

# Theo query: chạy trên mọi backing index
POST /logs-orders.app-default/_update_by_query
{ "query": { "term": { "order.id": "ORD-1" } },
  "script": { "source": "ctx._source.message = 'order created (corrected)'" } }

POST /logs-orders.app-default/_delete_by_query
{ "query": { "range": { "@timestamp": { "lt": "2026-01-01" } } } }

# Theo ID: phải nhắm vào đúng backing index (lấy từ _index trong kết quả search)
DELETE /.ds-logs-orders.app-default-2026.10.28-000001/_doc/<id>
# Chuyển index thường đã có thành data stream (cần alias và template phù hợp)
POST /_data_stream/_migrate/legacy-logs

# Xóa data stream: xóa luôn mọi backing index
DELETE /_data_stream/logs-orders.app-default

Data Stream Lifecycle

Từ ES 8.14, ngoài ILM còn có data stream lifecycle: cấu hình đơn giản hơn, khai báo bằng retention thay vì từng phase. Elasticsearch tự quyết định thời điểm rollover và tự tối ưu (force merge) backing index cũ.

# Trong index template
"template": {
  "lifecycle": { "data_retention": "30d" }
}

# Hoặc đặt trực tiếp cho data stream đã có
PUT /_data_stream/logs-orders.app-default/_lifecycle
{ "data_retention": "30d" }

GET /logs-orders.app-default/_lifecycle/explain
Data stream lifecycleILM
Cấu hìnhMột con số retention (và downsampling)Từng phase, từng action
Data tiers (hot/warm/cold)KhôngCó
Searchable snapshot, shrinkKhôngCó
Phù hợpChỉ cần "giữ N ngày rồi xóa"Cần chuyển tier, tối ưu chi phí theo giai đoạn

Khi một backing index có cả hai, ILM được ưu tiên (có thể đổi bằng setting index.lifecycle.prefer_ilm).

Time Series Data Stream

TSDS là data stream tối ưu cho metric: mỗi document là một mẫu đo của một chuỗi thời gian (time series) xác định bởi các dimension.

Khái niệmMappingVí dụ
Dimension"time_series_dimension": true (keyword, ip, số nguyên)host.name, pod.name, region
Gauge"time_series_metric": "gauge"CPU %, nhiệt độ, số kết nối đang mở
Counter"time_series_metric": "counter"Tổng request từ lúc khởi động, tổng byte đã gửi
PUT /_index_template/metrics-node
{
  "index_patterns": ["metrics-node.stats-*"],
  "data_stream": {},
  "priority": 200,
  "template": {
    "settings": {
      "index.mode": "time_series",
      "index.routing_path": ["host.name", "region"]
    },
    "mappings": { "properties": {
      "@timestamp":      { "type": "date" },
      "host.name":       { "type": "keyword", "time_series_dimension": true },
      "region":          { "type": "keyword", "time_series_dimension": true },
      "cpu.pct":         { "type": "double",  "time_series_metric": "gauge" },
      "memory.used":     { "type": "long",    "time_series_metric": "gauge" },
      "requests.total":  { "type": "long",    "time_series_metric": "counter" }
    } }
  }
}

TSDS khác data stream thường ở đâu

  • Routing theo dimension: mọi mẫu của cùng một time series nằm trong cùng shard, sắp xếp liền nhau theo thời gian → nén rất tốt
  • _id sinh từ dimension + @timestamp: gửi trùng một mẫu đo bị từ chối, không sinh dữ liệu trùng
  • Synthetic _source bật mặc định (xem dưới)
  • Cửa sổ thời gian: mỗi backing index nhận document trong một khoảng thời gian xác định (index.time_series.start_time/end_time). Document quá cũ hoặc quá xa trong tương lai so với khoảng đang nhận sẽ bị từ chối
Cardinality của dimension Mỗi tổ hợp giá trị dimension là một time series. Dùng giá trị thay đổi liên tục (request id, user id, timestamp dạng chuỗi) làm dimension sẽ sinh hàng triệu time series chỉ có một điểm, mất toàn bộ lợi ích nén. Dimension là "đo cái gì", không phải "mỗi lần đo là gì". 
# Tỷ lệ tăng của counter (từ ES 8.x, dùng cho TSDS)
GET /metrics-node.stats-default/_search
{
  "size": 0,
  "aggs": { "per_host": { "time_series": {},
    "aggs": { "req_rate": { "rate": { "field": "requests.total", "unit": "second" } } } } }
}

# ES|QL có hỗ trợ tốt cho time series ở các bản gần đây
POST /_query
{ "query": "FROM metrics-node.stats-* | STATS avg_cpu = AVG(cpu.pct) BY host.name, bucket = BUCKET(@timestamp, 5 minutes)" }

Downsampling

Downsampling gộp các mẫu đo của một time series trong mỗi khoảng thời gian thành một document tóm tắt. Metric dạng gauge giữ min, max, sum, value_count (tính lại được trung bình); counter giữ giá trị cuối.

Độ tuổi dữ liệuĐộ phân giảiSố document mỗi time series mỗi ngày
0–7 ngày10 giây (gốc)8.640
7–30 ngày5 phút288
30–365 ngày1 giờ24
# Qua data stream lifecycle
PUT /_data_stream/metrics-node.stats-default/_lifecycle
{
  "data_retention": "365d",
  "downsampling": [
    { "after": "7d",  "fixed_interval": "5m" },
    { "after": "30d", "fixed_interval": "1h" }
  ]
}

# Hoặc qua ILM: action "downsample" ở phase warm/cold
"warm": { "min_age": "7d", "actions": { "downsample": { "fixed_interval": "5m" } } }

# Thủ công trên một backing index (index phải read-only)
PUT /.ds-metrics-node.stats-default-2026.10.01-000001/_block/write
POST /.ds-metrics-node.stats-default-2026.10.01-000001/_downsample/metrics-node-5m-2026.10.01
{ "fixed_interval": "5m" }
Query không cần thay đổi Dashboard query trên data stream tiếp tục hoạt động sau downsampling. Aggregation avg, max trên dữ liệu đã gộp vẫn cho kết quả đúng; date_histogram chỉ cần interval không nhỏ hơn độ phân giải của dữ liệu đã gộp.

Synthetic _source

Bình thường Elasticsearch lưu nguyên văn JSON gốc trong _source, chiếm phần lớn dung lượng index. Synthetic _source không lưu bản gốc mà dựng lại nó từ doc_values và stored field khi cần.

PUT /_index_template/logs-compact
{
  "index_patterns": ["logs-compact-*"],
  "data_stream": {},
  "template": {
    "settings": { "index.mapping.source.mode": "synthetic" }
  }
}
# Phiên bản cũ hơn dùng mapping: "mappings": { "_source": { "mode": "synthetic" } }
ƯuĐánh đổi
Giảm đáng kể dung lượng lưu trữ_source dựng lại có thể khác bản gốc: field sắp xếp lại, mảng có thể bị sắp xếp và bỏ trùng, định dạng số/ngày được chuẩn hóa
Bật mặc định cho TSDSĐọc _source chậm hơn một chút vì phải dựng lại
Dùng được cho log (LogsDB index mode, ES 8.17+)Cần license trả phí ngoài TSDS (đối chiếu Elastic Subscriptions cho đúng version)
Khi nào không dùng Nếu bạn cần trả về chính xác từng byte của document gốc (ví dụ lưu trữ phục vụ kiểm toán, hoặc dùng reindex để chuyển dữ liệu mà phải giữ nguyên định dạng), hãy giữ _source chuẩn.

Bài Lab: Ingest Metric Với TSDS + Downsampling

Bước 1: Template TSDS

source .env
curl $AUTH -X PUT "$ES/_index_template/metrics-lab.node" -H 'Content-Type: application/json' -d '{
  "index_patterns": ["metrics-lab.node-*"],
  "data_stream": {},
  "priority": 200,
  "template": {
    "settings": { "index.mode": "time_series", "index.routing_path": ["host.name"], "number_of_replicas": 0 },
    "mappings": { "properties": {
      "@timestamp":     { "type": "date" },
      "host.name":      { "type": "keyword", "time_series_dimension": true },
      "cpu.pct":        { "type": "double",  "time_series_metric": "gauge" },
      "requests.total": { "type": "long",    "time_series_metric": "counter" }
    } }
  }
}'

Bước 2: Sinh 2 giờ dữ liệu cho 3 host, mỗi 10 giây

python - <<'PY' > metrics.ndjson
import datetime, json, random
now = datetime.datetime.now(datetime.timezone.utc).replace(microsecond=0)
start = now - datetime.timedelta(hours=2)
total = {"web-1": 0, "web-2": 0, "db-1": 0}
t = start
while t < now:
    for host in total:
        total[host] += random.randint(50, 150)
        print(json.dumps({"create": {}}))
        print(json.dumps({"@timestamp": t.strftime("%Y-%m-%dT%H:%M:%SZ"), "host.name": host,
                          "cpu.pct": round(random.uniform(10, 90), 2), "requests.total": total[host]}))
    t += datetime.timedelta(seconds=10)
PY
wc -l metrics.ndjson     # khoảng 4.320 dòng = 2.160 document

curl $AUTH -s -X POST "$ES/metrics-lab.node-default/_bulk?refresh=true" \
  -H 'Content-Type: application/x-ndjson' --data-binary @metrics.ndjson | python -c "import sys,json;print('errors:',json.load(sys.stdin)['errors'])"
Dữ liệu nằm ngoài cửa sổ thời gian TSDS mới tạo nhận dữ liệu trong khoảng mặc định vài giờ quanh thời điểm hiện tại (index.look_back_time, mặc định 2 giờ). Script trên sinh đúng 2 giờ trở về trước. Nếu errors: true với lỗi timestamp nằm ngoài khoảng, rút ngắn khoảng sinh dữ liệu xuống 1 giờ 50 phút.

Bước 3: Thử gửi trùng và truy vấn

# Gửi lại đúng một mẫu đã có → bị từ chối 409 vì _id sinh từ dimension + @timestamp
head -n 2 metrics.ndjson | curl $AUTH -s -X POST "$ES/metrics-lab.node-default/_bulk" \
  -H 'Content-Type: application/x-ndjson' --data-binary @- | python -m json.tool | grep -E '"status"|"type"'

curl $AUTH "$ES/metrics-lab.node-default/_search?size=0&pretty" -H 'Content-Type: application/json' -d '{
  "aggs": { "per_host": { "terms": { "field": "host.name" },
    "aggs": { "cpu": { "avg": { "field": "cpu.pct" } } } } } }'

Bước 4: Downsampling thủ công và so sánh

BACKING=$(curl -s $AUTH "$ES/_data_stream/metrics-lab.node-default" | python -c "import sys,json;print(json.load(sys.stdin)['data_streams'][0]['indices'][0]['index_name'])")
echo $BACKING

# Rollover để backing index hiện tại không còn là write index, rồi chặn ghi
curl $AUTH -X POST "$ES/metrics-lab.node-default/_rollover"
curl $AUTH -X PUT "$ES/$BACKING/_block/write"
curl $AUTH -X POST "$ES/$BACKING/_downsample/lab-node-5m" -H 'Content-Type: application/json' -d '{"fixed_interval":"5m"}'

curl $AUTH "$ES/_cat/indices/$BACKING,lab-node-5m?v&h=index,docs.count,store.size"
curl $AUTH "$ES/lab-node-5m/_search?size=1&pretty&sort=@timestamp"

Bước 5: Cấu hình tự động cho lần sau

curl $AUTH -X PUT "$ES/_data_stream/metrics-lab.node-default/_lifecycle" -H 'Content-Type: application/json' -d '{
  "data_retention": "30d",
  "downsampling": [ { "after": "1d", "fixed_interval": "5m" }, { "after": "7d", "fixed_interval": "1h" } ]
}'
curl $AUTH "$ES/metrics-lab.node-default/_lifecycle/explain?pretty"
Xác minh thành công Index gốc có khoảng 2.160 document, index downsample 5 phút còn khoảng 72 (3 host × 24 khoảng 5 phút). Document sau downsampling chứa cpu.pct dạng min/max/sum/value_count. Mẫu gửi trùng bị từ chối với 409. Từ giờ data stream tự downsampling và tự xóa sau 30 ngày.

Câu Hỏi Ôn Tập

  1. Data stream gồm những thành phần nào? Ghi và đọc đi vào backing index nào?
  2. Vì sao không ghi đè document theo ID qua tên data stream được? Làm thế nào để sửa một document?
  3. Giải thích naming scheme type-dataset-namespace và lợi ích khi phân quyền.
  4. Khi nào chọn data stream lifecycle, khi nào chọn ILM?
  5. Dimension và metric trong TSDS khác nhau thế nào? Vì sao không dùng request id làm dimension?
  6. Downsampling giữ lại những giá trị nào của gauge? Vì sao vẫn tính được trung bình?
  7. Synthetic _source tiết kiệm dung lượng bằng cách nào, và đánh đổi gì?

Checklist Kiến Thức

  • ☐ Tạo data stream qua index template
  • ☐ Đặt tên theo naming scheme của Elastic
  • ☐ Rollover, cập nhật mapping, update/delete by query trên data stream
  • ☐ Cấu hình data stream lifecycle với retention
  • ☐ Viết mapping TSDS với dimension, gauge, counter
  • ☐ Downsampling qua lifecycle, ILM và thủ công
  • ☐ Biết khi nào dùng và không dùng synthetic _source

Lỗi Thường Gặp

Những lỗi phổ biến:
  • Thiếu @timestamp: document bị từ chối khi ghi vào data stream.
  • Template priority thấp hơn template có sẵn: data stream được tạo với mapping mặc định thay vì mapping của bạn.
  • Dùng dấu gạch ngang trong dataset: phá vỡ naming scheme, quyền theo pattern không khớp.
  • Dimension có cardinality cao: TSDS mất khả năng nén, cluster tốn tài nguyên.
  • Gửi dữ liệu cũ vào TSDS: bị từ chối vì nằm ngoài cửa sổ thời gian của backing index.
  • Downsampling quá sớm: mất độ phân giải cần cho điều tra sự cố gần đây.

Best Practices & Tài Liệu Tham Khảo

Best Practices

  • Dùng data stream cho mọi dữ liệu log, metric, event append-only
  • Theo naming scheme để tận dụng template có sẵn và phân quyền theo namespace
  • Kế thừa component template logs@*, metrics@* thay vì viết lại toàn bộ
  • Metric dùng TSDS, chọn dimension có cardinality hợp lý
  • Downsampling theo nhu cầu điều tra: giữ độ phân giải gốc đủ lâu để xử lý sự cố
  • Data stream lifecycle cho retention đơn giản, ILM khi cần data tiers
