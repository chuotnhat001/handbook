Fleet & Integrations

Fleet Server, agent policy, integrations, enrollment, nâng cấp và theo dõi agent tập trung

Nguồn: Elastic — Fleet and Elastic Agent, Elastic — Fleet Server

Mục Tiêu Học Tập

Sau khi hoàn thành bài này, bạn sẽ: Hiểu kiến trúc Fleet gồm Kibana, Fleet Server, Elastic Agent và Elasticsearch. Triển khai Fleet Server. Tạo agent policy và gắn integrations. Enroll agent bằng enrollment token. Nâng cấp agent hàng loạt và theo dõi sức khỏe của chúng. Tự động hóa bằng Fleet API, và biết khi nào chạy agent standalone.

Kiến Trúc Fleet

Kibana (Fleet UI) → Elasticsearch (lưu policy) → Fleet Server → Elastic Agents → Elasticsearch (dữ liệu)
Thành phầnVai trò
Kibana Fleet appGiao diện quản lý: policy, integration, danh sách agent, nâng cấp
ElasticsearchLưu policy và trạng thái agent trong index hệ thống .fleet-*, đồng thời nhận dữ liệu agent gửi lên
Fleet ServerĐiểm kết nối của agent: nhận check-in, phát policy mới, cấp API key cho agent
Elastic AgentChạy trên máy nguồn, nhận policy, thu thập dữ liệu, gửi thẳng tới output (Elasticsearch, Logstash, Kafka)
Tư duy cốt lõi Agent không bao giờ gọi Kibana. Agent nói chuyện với Fleet Server để lấy cấu hình (control plane), và gửi dữ liệu thẳng tới output (data plane). Fleet Server chết thì agent vẫn tiếp tục gửi dữ liệu theo policy cuối cùng đã nhận, chỉ không nhận được thay đổi mới.

Fleet Server

Fleet Server thực chất là một Elastic Agent chạy integration fleet_server. Nó xác thực với Elasticsearch bằng service token của service account elastic/fleet-server.

# Tạo service token cho Fleet Server
POST /_security/service/elastic/fleet-server/credential/token/fleet-server-01
# Cài Fleet Server trên một host Linux
sudo ./elastic-agent install \
  --fleet-server-es=https://es01:9200 \
  --fleet-server-service-token=<service-token> \
  --fleet-server-policy=fleet-server-policy \
  --fleet-server-es-ca=/etc/certs/ca.crt \
  --certificate-authorities=/etc/certs/ca.crt \
  --fleet-server-cert=/etc/certs/fleet.crt \
  --fleet-server-cert-key=/etc/certs/fleet.key \
  --url=https://fleet.internal:8220
  • Cổng mặc định 8220, phục vụ HTTPS. Agent phải tin certificate của Fleet Server
  • Khai báo địa chỉ Fleet Server trong Kibana (Fleet → Settings → Fleet server hosts) để agent biết kết nối vào đâu
  • Production chạy ít nhất 2 Fleet Server sau load balancer. Một Fleet Server phục vụ được vài nghìn agent tùy phần cứng và tần suất check-in

Agent Policies

Agent policy là tập cấu hình áp cho một nhóm agent: integrations nào, output nào, namespace nào, có thu thập log/metric của chính agent không. Mỗi agent thuộc đúng một policy.

Ví dụ policyIntegrationsÁp cho
linux-webSystem, NginxMáy chủ web
linux-dbSystem, PostgreSQLMáy chủ database
windows-desktopSystem, Windows, Elastic DefendMáy trạm nhân viên
# Mỗi lần sửa policy, revision tăng lên và mọi agent trong policy nhận bản mới ở lần check-in kế tiếp
GET kbn:/api/fleet/agent_policies?perPage=20
Namespace Policy có trường namespace, trở thành phần cuối của tên data stream: logs-nginx.access-production. Tách namespace theo môi trường (production, staging) hoặc theo team giúp áp ILM và quyền đọc khác nhau cho từng nhóm (Bài 23).

Integrations

Integration là package đóng gói cách thu thập một nguồn dữ liệu, tương tự module của Beats nhưng phong phú hơn: input cho agent, ingest pipeline, index template theo ECS, dashboard, và đôi khi cả rule phát hiện tấn công.

  • Catalog có hàng trăm integration: hệ điều hành, web server, database, cloud (AWS, Azure, GCP), mạng, bảo mật
  • Integration được version hóa độc lập với Stack, cập nhật được mà không cần nâng cấp Elasticsearch
  • Thêm integration vào policy, cấu hình biến (đường dẫn log, host, thông tin đăng nhập), lưu lại là xong
# Cài một integration package vào cluster (template, pipeline, dashboard)
POST kbn:/api/fleet/epm/packages/nginx

# Thêm integration vào policy (package policy)
POST kbn:/api/fleet/package_policies
{
  "policy_id": "<agent-policy-id>",
  "package": { "name": "nginx", "version": "<version>" },
  "name": "nginx-web",
  "namespace": "production",
  "inputs": { ... }
}
Secret trong integration Mật khẩu database hoặc API key của dịch vụ nhập vào integration được gửi xuống agent qua policy. Từ các bản 8.x gần đây, Fleet hỗ trợ lưu một số biến dạng secret riêng, không hiển thị trong policy. Dù vậy, hãy cấp cho tài khoản thu thập metric quyền chỉ đọc tối thiểu.

Enrollment

Agent tham gia Fleet bằng enrollment token. Mỗi token gắn với một agent policy, nên token quyết định agent mới nhận cấu hình nào.

# Lấy enrollment token (Fleet → Enrollment tokens, hoặc API)
GET kbn:/api/fleet/enrollment_api_keys

# Enroll và cài agent dạng service trên Linux
sudo ./elastic-agent install \
  --url=https://fleet.internal:8220 \
  --enrollment-token=<token> \
  --certificate-authorities=/etc/certs/ca.crt
  • Khi enroll, Fleet Server cấp cho agent một API key riêng. Thu hồi agent (unenroll) là vô hiệu hóa key đó
  • Enrollment token có thể thu hồi khi bị lộ, agent đã enroll không bị ảnh hưởng
  • Trên Kubernetes, agent chạy dạng DaemonSet với token truyền qua Secret

Nâng Cấp & Sức Khỏe

Trạng thái agentÝ nghĩa
HealthyCheck-in đều đặn, mọi input chạy bình thường
UnhealthyCòn check-in nhưng có input lỗi (sai đường dẫn, sai mật khẩu...)
OfflineKhông check-in trong một khoảng thời gian (máy tắt, mất mạng)
UpdatingĐang nhận policy mới hoặc đang nâng cấp
InactiveOffline quá lâu, bị ẩn khỏi danh sách mặc định

Nâng cấp agent từ Kibana: chọn agent (hoặc lọc theo policy), chọn version, đặt rollout để nâng cấp dần thay vì cùng lúc. Agent tự tải binary, thay thế và rollback nếu bản mới không khởi động được.

# Nâng cấp hàng loạt theo policy, trải đều trong 1 giờ
POST kbn:/api/fleet/agents/bulk_upgrade
{
  "agents": "policy_id:<agent-policy-id>",
  "version": "8.15.0",
  "rollout_duration_seconds": 3600
}
Thứ tự nâng cấp Elastic Agent không được mới hơn Fleet Server, và Fleet Server không được mới hơn Elasticsearch/Kibana. Nâng cấp theo thứ tự: Elasticsearch → Kibana → Fleet Server → các agent.

Bật "Collect agent logs and metrics" trong policy để agent gửi log và metric của chính nó lên cluster. Khi agent unhealthy, xem log của nó ngay trong Fleet mà không cần đăng nhập máy nguồn.

Fleet API

Mọi thao tác trên Fleet UI đều có API tương ứng. Dùng API để quản lý policy dạng code (Terraform provider của Elastic hoặc script trong CI).

# Tạo agent policy
curl $AUTH -X POST "http://localhost:5601/api/fleet/agent_policies" \
  -H 'kbn-xsrf: true' -H 'Content-Type: application/json' -d '{
  "name": "linux-web", "namespace": "production",
  "monitoring_enabled": ["logs", "metrics"]
}'

# Liệt kê agent unhealthy hoặc offline
curl $AUTH "http://localhost:5601/api/fleet/agents?kuery=status:unhealthy%20or%20status:offline" -H 'kbn-xsrf: true'

# Chuyển agent sang policy khác
curl $AUTH -X POST "http://localhost:5601/api/fleet/agents/<agent-id>/reassign" \
  -H 'kbn-xsrf: true' -H 'Content-Type: application/json' -d '{"policy_id":"<new-policy-id>"}'

Ký hiệu kbn:/api/... trong các ví dụ trước dùng được trực tiếp trong Kibana Dev Tools Console để gọi API của Kibana.

Standalone Agent

Agent standalone không kết nối Fleet, đọc cấu hình từ file elastic-agent.yml. Lấy file mẫu từ Fleet UI (Add agent → Run standalone) để có sẵn cấu hình của integration.

Fleet-managedStandalone
Đổi cấu hìnhSửa policy trên KibanaSửa file, tự phân phối (Ansible, GitOps, Helm)
Cần Fleet ServerCóKhông
Nâng cấp từ xaCóKhông, tự quản lý
Phù hợpĐa số triển khaiMôi trường bị cô lập mạng, quy trình GitOps nghiêm ngặt, Kubernetes quản lý bằng manifest

Bài Lab: Quản Lý 3 Agent Qua Fleet

Lab chạy Fleet Server và 3 agent trong Docker, dùng chung cluster có TLS từ Bài 13. Để gọn, Fleet Server trong lab phục vụ HTTP không TLS. Production luôn dùng HTTPS cho Fleet Server.

Bước 1: Khai báo Fleet trong Kibana

Thêm vào phần environment của service kibana, rồi docker compose up -d kibana:

      - XPACK_FLEET_AGENTS_FLEET_SERVER_HOSTS=["http://fleet-server:8220"]
      - XPACK_FLEET_AGENTS_ELASTICSEARCH_HOSTS=["https://es01:9200"]

Agent cần tin CA của Elasticsearch để gửi dữ liệu. Trong Kibana, vào Fleet → Settings → Outputs → sửa output mặc định, dán nội dung certs/ca/ca.crt vào ô "Elasticsearch CA trusted fingerprint" (dạng SHA-256) hoặc phần "Advanced YAML configuration":

# Lấy fingerprint SHA-256 của CA
openssl x509 -fingerprint -sha256 -noout -in certs/ca/ca.crt | cut -d= -f2 | tr -d ':'

# Hoặc trong Advanced YAML configuration của output:
ssl.certificate_authorities: ["/certs/ca/ca.crt"]

Bước 2: Service token và Fleet Server

source .env
curl $AUTH -X POST "$ES/_security/service/elastic/fleet-server/credential/token/lab-fleet" \
  | python -c "import sys,json;print('FLEET_SERVICE_TOKEN='+json.load(sys.stdin)['token']['value'])" >> .env
  fleet-server:
    image: docker.elastic.co/beats/elastic-agent:8.15.0
    user: root
    depends_on: [ kibana ]
    ports: [ "8220:8220" ]
    environment:
      - FLEET_SERVER_ENABLE=1
      - FLEET_SERVER_ELASTICSEARCH_HOST=https://es01:9200
      - FLEET_SERVER_ELASTICSEARCH_CA=/certs/ca/ca.crt
      - FLEET_SERVER_SERVICE_TOKEN=${FLEET_SERVICE_TOKEN}
      - FLEET_SERVER_POLICY_ID=fleet-server-policy
      - FLEET_SERVER_INSECURE_HTTP=1
      - FLEET_URL=http://fleet-server:8220
      - KIBANA_FLEET_SETUP=1
      - KIBANA_FLEET_HOST=http://kibana:5601
      - KIBANA_FLEET_USERNAME=elastic
      - KIBANA_FLEET_PASSWORD=${ELASTIC_PASSWORD}
    volumes:
      - ./certs:/certs:ro
docker compose up -d fleet-server
docker compose logs -f fleet-server | grep -i "fleet server"
# Kibana → Fleet → Agents: thấy agent của Fleet Server ở trạng thái Healthy
Tên biến môi trường theo version Các biến FLEET_SERVER_* và KIBANA_FLEET_* trên đây theo tài liệu container Elastic Agent của dòng 8.x. Nếu Fleet Server không khởi động, đối chiếu trang "Elastic Agent in a container" cho đúng version bạn dùng.

Bước 3: Agent policy với System integration

  1. Fleet → Agent policies → Create: tên lab-linux, namespace lab, bật thu thập log và metric của agent
  2. Mở policy → Add integration → System. Giữ cấu hình mặc định, lưu
  3. Fleet → Enrollment tokens: copy token của policy lab-linux, lưu vào .env dạng LAB_ENROLL_TOKEN=...

Bước 4: Enroll 3 agent

  agent:
    image: docker.elastic.co/beats/elastic-agent:8.15.0
    user: root
    depends_on: [ fleet-server ]
    environment:
      - FLEET_ENROLL=1
      - FLEET_URL=http://fleet-server:8220
      - FLEET_ENROLLMENT_TOKEN=${LAB_ENROLL_TOKEN}
      - FLEET_INSECURE=1
    volumes:
      - ./certs:/certs:ro
docker compose up -d --scale agent=3 agent
# Fleet → Agents: 3 agent mới thuộc policy lab-linux, trạng thái Healthy sau khoảng 1 phút

Bước 5: Thay đổi policy và quan sát

  1. Thêm integration Nginx vào policy lab-linux với đường dẫn log không tồn tại. Quan sát revision của policy tăng, cả 3 agent chuyển Updating rồi Healthy hoặc Unhealthy tùy input
  2. Mở một agent → tab Logs: đọc log của agent ngay trong Kibana
  3. Xóa integration Nginx, quan sát agent trở về trạng thái cũ
curl $AUTH "$ES/_data_stream/*-lab?filter_path=**.name"
# metrics-system.cpu-lab, metrics-system.memory-lab, logs-system.syslog-lab ...
curl $AUTH -X GET "http://localhost:5601/api/fleet/agents?kuery=policy_id:*" -H 'kbn-xsrf: true' \
  | python -c "import sys,json;[print(a['local_metadata']['host']['hostname'],a['status']) for a in json.load(sys.stdin)['items']]"
Xác minh thành công Bốn agent (Fleet Server + 3 agent) xuất hiện trong Fleet. Data stream với namespace lab chứa metric hệ thống từ cả 3 agent. Sửa policy trên Kibana một lần là cả 3 agent nhận cấu hình mới, không cần đăng nhập container nào.

Lỗi Thường Gặp

Những lỗi phổ biến:
  • Agent không tin CA của Elasticsearch: agent Healthy nhưng không có dữ liệu. Cấu hình CA hoặc fingerprint ở output.
  • Chỉ một Fleet Server: Fleet Server chết là không triển khai được thay đổi nào.
  • Agent mới hơn Fleet Server: agent không enroll được hoặc không nhận policy.
  • Một policy khổng lồ cho mọi máy: máy nào cũng chạy input không liên quan, sinh lỗi và tốn tài nguyên.
  • Nâng cấp toàn bộ agent cùng lúc: lỗi của bản mới ảnh hưởng toàn hệ thống. Dùng rollout và nâng cấp nhóm nhỏ trước.
  • Fleet Server dùng HTTP ở production: token và API key của agent đi dạng rõ trên mạng.

Best Practices & Tài Liệu Tham Khảo

Best Practices

  • Ít nhất 2 Fleet Server sau load balancer, certificate do CA nội bộ cấp
  • Policy theo vai trò máy (web, db, desktop), namespace theo môi trường
  • Bật thu thập log và metric của agent để chẩn đoán từ xa
  • Nâng cấp theo thứ tự Stack → Fleet Server → agent, dùng rollout
  • Quản lý policy bằng Fleet API hoặc Terraform cho môi trường lớn
  • Cảnh báo khi số agent offline vượt ngưỡng (Bài 18)
