Kibana — Visualization & Management

Data view, Discover, KQL, Lens, Dashboard, Spaces, saved objects, Dev Tools

Nguồn: Elastic — Kibana Guide, Elastic — KQL

Mục Tiêu Học Tập

Sau khi hoàn thành bài này, bạn sẽ: Kết nối Kibana với cluster đã bật security. Tạo data view và khám phá dữ liệu trong Discover bằng KQL. Dựng visualization bằng Lens và ghép thành dashboard. Tách môi trường làm việc bằng Spaces và phân quyền theo role. Export/import saved objects để đưa dashboard giữa các môi trường. Dùng Dev Tools Console thành thạo.

Kết Nối Kibana Với Elasticsearch

Kibana là ứng dụng Node.js, giao diện web cho Elasticsearch. Kibana không lưu dữ liệu riêng: mọi cấu hình (dashboard, data view, rule) đều lưu trong các index hệ thống của Elasticsearch.

# kibana.yml
server.host: "0.0.0.0"
server.publicBaseUrl: "https://kibana.example.com"
elasticsearch.hosts: [ "https://es01:9200", "https://es02:9200" ]
elasticsearch.username: "kibana_system"
elasticsearch.ssl.certificateAuthorities: [ "/usr/share/kibana/config/certs/ca/ca.crt" ]

# Khóa mã hóa saved objects (bắt buộc cho alerting và connector), dài tối thiểu 32 ký tự
xpack.encryptedSavedObjects.encryptionKey: "<32+ ký tự ngẫu nhiên>"
# Lưu mật khẩu vào keystore của Kibana, không để trong kibana.yml
bin/kibana-keystore create
bin/kibana-keystore add elasticsearch.password

# Sinh sẵn 3 khóa mã hóa
bin/kibana-encryption-keys generate
Version phải khớp Kibana phải cùng version với Elasticsearch (Bài 04). Kibana mới hơn cluster sẽ từ chối khởi động. Khi nâng cấp, nâng Elasticsearch trước, Kibana sau.

Với cluster mới cài ES 8.x một node, cách nhanh nhất là dùng enrollment token: mở Kibana, dán token sinh bởi bin/elasticsearch-create-enrollment-token -s kibana, Kibana tự nhận CA và cấu hình kết nối.

Data Views

Data view (trước đây gọi là index pattern) cho Kibana biết cần đọc index hoặc data stream nào, và field nào là trường thời gian.

# Tạo data view qua API (tiện cho automation)
curl $AUTH -X POST "http://localhost:5601/api/data_views/data_view" \
  -H 'kbn-xsrf: true' -H 'Content-Type: application/json' -d '{
  "data_view": { "title": "logs-*", "name": "Logs", "timeFieldName": "@timestamp" }
}'
  • Pattern dùng wildcard: logs-*, logs-app-*,logs-web-*, hoặc cross-cluster remote:logs-* (Bài 22)
  • Chọn đúng time field để bộ chọn thời gian trên mọi màn hình hoạt động
  • Có thể thêm runtime field ngay trong data view, tính khi truy vấn, không cần reindex

Discover & KQL

Discover là nơi khám phá document thô: lọc theo thời gian, tìm kiếm, chọn cột, xem chi tiết từng document.

KQL (Kibana Query Language)

Mục đíchKQL
Khớp giá trịstatus_code: 500
Nhiều giá trịmethod: (GET or POST)
Kết hợpstatus_code >= 500 and path: "/api/orders"
Phủ địnhnot user_agent: curl
Field tồn tạierror.message: *
Wildcardpath: /api/prod*
Field lồng nhau (nested)items: { sku: "A1" and qty > 2 }
KQL, Lucene query hay ES|QL KQL là mặc định và đủ dùng cho hầu hết việc lọc. Lucene query syntax hỗ trợ regex và fuzzy (name:labtop~). ES|QL (Elasticsearch Query Language, có từ 8.11) là ngôn ngữ dạng pipe, cho phép biến đổi và tổng hợp ngay trong Discover: FROM logs-* | WHERE status_code >= 500 | STATS errors = COUNT(*) BY path | SORT errors DESC

Ngoài thanh tìm kiếm, filter pill (bấm vào giá trị field để thêm filter) dịch sang bool.filter trong Query DSL, có thể ghim (pin) để giữ khi chuyển màn hình.

Lens

Lens là trình tạo visualization kéo-thả: kéo field vào khung, Lens gợi ý loại biểu đồ và sinh aggregation tương ứng (Bài 09).

Mục đíchLoại biểu đồAggregation bên dưới
Xu hướng theo thời gianLine, area, bar (trục X là thời gian)date_histogram + metric
So sánh nhómBar ngangterms + metric
Tỷ lệPie, donut, treemapterms
Một con số quan trọngMetricsum, avg, cardinality
Phân bố hai chiềuHeat maphai bucket lồng nhau
Bảng chi tiếtTablenhiều bucket + metric
  • Formula: tính chỉ số từ nhiều metric, ví dụ tỷ lệ lỗi count(kql='status_code >= 500') / count()
  • Time shift: so sánh với kỳ trước (1w) ngay trên cùng biểu đồ
  • Inspect: xem request Elasticsearch mà Lens gửi đi. Đây là công cụ debug dashboard chậm

Dashboards & Canvas

Dashboard ghép nhiều panel (Lens, saved search, Markdown, map) dùng chung bộ chọn thời gian và filter.

  • Controls: dropdown hoặc slider ở đầu dashboard để người xem tự lọc (môi trường, service, khu vực)
  • Drilldown: bấm vào một điểm dữ liệu để mở dashboard khác hoặc Discover với filter tương ứng
  • Chia sẻ: link có trạng thái, nhúng iframe, hoặc báo cáo PDF/PNG định kỳ (reporting cần license trả phí)

Canvas dựng trang trình bày tự do theo pixel, phù hợp cho màn hình treo tường hoặc báo cáo có bố cục riêng. Với nhu cầu dashboard thông thường, Dashboard + Lens nhanh và dễ bảo trì hơn.

Dashboard chậm Mỗi panel là một hoặc nhiều request. Dashboard 30 panel trên khoảng thời gian 90 ngày có thể đè nặng cluster. Giảm số panel, đặt khoảng thời gian mặc định ngắn, và dùng Inspect để tìm panel tốn kém nhất.

Spaces & Phân Quyền

Space chia Kibana thành các không gian riêng: mỗi space có dashboard, data view, saved object riêng. Ví dụ: space cho team Payments, space cho team SRE.

Quyền trong Kibana cấu hình qua role của Elasticsearch, gồm hai phần:

  • Index privileges: được đọc dữ liệu index nào (Bài 13)
  • Kibana privileges: trong space nào, được dùng tính năng gì, mức read hay all
# Role cho team Payments: xem dashboard trong space "payments", chỉ đọc log của mình
curl $AUTH -X PUT "http://localhost:5601/api/security/role/payments_viewer" \
  -H 'kbn-xsrf: true' -H 'Content-Type: application/json' -d '{
  "elasticsearch": {
    "indices": [ { "names": ["logs-payments-*"], "privileges": ["read","view_index_metadata"] } ]
  },
  "kibana": [
    { "spaces": ["payments"], "base": [], "feature": { "dashboard": ["read"], "discover": ["read"] } }
  ]
}'
Space không phải ranh giới bảo mật dữ liệu Space chỉ tách các đối tượng của Kibana. Nếu role có quyền read trên logs-*, người dùng vẫn đọc được mọi log, từ bất kỳ space nào, qua Dev Tools hoặc API. Ranh giới dữ liệu phải đặt ở index privileges hoặc document level security.

Saved Objects

Dashboard, visualization, data view, saved search đều là saved object. Chúng có thể export ra file NDJSON và import sang Kibana khác, giúp đưa dashboard từ staging lên production hoặc quản lý bằng Git.

# Export dashboard kèm mọi object nó tham chiếu
curl $AUTH -X POST "http://localhost:5601/api/saved_objects/_export" \
  -H 'kbn-xsrf: true' -H 'Content-Type: application/json' \
  -d '{"objects":[{"type":"dashboard","id":"<dashboard-id>"}],"includeReferencesDeep":true}' \
  -o access-logs-dashboard.ndjson

# Import vào space "payments", ghi đè nếu đã có
curl $AUTH -X POST "http://localhost:5601/s/payments/api/saved_objects/_import?overwrite=true" \
  -H 'kbn-xsrf: true' --form file=@access-logs-dashboard.ndjson

Các ví dụ dùng biến $AUTH từ Lab Bài 13 và Kibana lab chạy HTTP ở cổng 5601. Production nên bật TLS cho Kibana (server.ssl.*) và đổi sang https://. Mọi request ghi tới Kibana API cần header kbn-xsrf để chống CSRF. Thêm tiền tố /s/<space-id> để thao tác trong space không phải mặc định.

Dev Tools

Console trong Dev Tools là nơi gửi request REST tới Elasticsearch với autocomplete, định dạng JSON, và lịch sử. Toàn bộ ví dụ dạng GET /index/_search trong giáo trình này chạy trực tiếp được ở đây.

  • Ctrl/Cmd + Enter: chạy request tại con trỏ
  • Menu "Copy as cURL": chuyển request sang lệnh curl để dùng trong script
  • Search Profiler: trực quan hóa Profile API (Bài 19)
  • Grok Debugger: thử pattern grok trước khi đưa vào Logstash hoặc ingest pipeline (Bài 15)
  • Painless Lab: thử script Painless

Console chạy với quyền của người dùng đang đăng nhập, nên role giới hạn quyền vẫn áp dụng.

Bài Lab: Dashboard Monitoring Cho Web Application

Bước 1: Thêm Kibana vào docker-compose.yml

Đặt mật khẩu cho kibana_system và thêm vào .env:

source .env
curl $AUTH -X POST "$ES/_security/user/kibana_system/_password" \
  -H 'Content-Type: application/json' -d '{"password":"kibana-lab-password-123"}'
echo "KIBANA_PASSWORD=kibana-lab-password-123" >> .env
echo "KIBANA_ENC_KEY=$(openssl rand -hex 32)" >> .env
  kibana:
    image: docker.elastic.co/kibana/kibana:8.15.0
    depends_on: [ es01 ]
    ports: [ "5601:5601" ]
    environment:
      - ELASTICSEARCH_HOSTS=https://es01:9200
      - ELASTICSEARCH_USERNAME=kibana_system
      - ELASTICSEARCH_PASSWORD=${KIBANA_PASSWORD}
      - ELASTICSEARCH_SSL_CERTIFICATEAUTHORITIES=config/certs/ca/ca.crt
      - XPACK_ENCRYPTEDSAVEDOBJECTS_ENCRYPTIONKEY=${KIBANA_ENC_KEY}
    volumes:
      - ./certs:/usr/share/kibana/config/certs
docker compose up -d kibana
docker compose logs -f kibana | grep -i "available"
# Mở http://localhost:5601, đăng nhập bằng user elastic

Bước 2: Nạp dữ liệu access log

Trong Dev Tools Console, chạy lại phần tạo index và bulk của Lab Bài 09 (access-logs), rồi thêm nhiều bản ghi hơn để biểu đồ có hình dạng. Nếu dùng Kibana sample data (Home → Add data → Sample web logs), bạn có sẵn khoảng 14.000 bản ghi web log.

Bước 3: Data view và Discover

  1. Stack Management → Data Views → Create: tên Access Logs, pattern access-logs, time field @timestamp
  2. Mở Discover, chọn data view, đặt khoảng thời gian bao quanh dữ liệu
  3. Thử KQL: status_code >= 500, rồi path: "/api/products" and latency_ms > 1000
  4. Thêm cột path, status_code, latency_ms, lưu thành saved search "Lỗi 5xx"

Bước 4: Bốn panel bằng Lens

PanelCấu hình
Requests theo thời gianBar, trục X @timestamp, trục Y Count, breakdown theo status_code (top 5)
Tỷ lệ lỗiMetric, Formula: count(kql='status_code >= 500') / count(), định dạng phần trăm
P95 latencyLine, trục Y: Percentile 95 của latency_ms
Top endpoint chậmBar ngang, Top 10 path theo Average latency_ms

Lưu cả bốn vào dashboard "Web App Monitoring", thêm saved search "Lỗi 5xx" ở cuối. Thêm control dạng options list cho field method.

Bước 5: Space, role và export

  1. Tạo space sre, copy dashboard sang space này (Stack Management → Saved Objects → Copy to space)
  2. Tạo role chỉ read dashboard trong space sre và read index access-logs, gán cho một user mới, đăng nhập thử bằng cửa sổ ẩn danh
  3. Export dashboard ra NDJSON bằng API ở mục Saved Objects
Xác minh thành công Dashboard hiển thị đủ 4 panel và đổi theo bộ chọn thời gian. User mới chỉ thấy space sre, mở được dashboard nhưng không sửa được. File NDJSON chứa dashboard, các visualization và data view. Bấm Inspect trên panel P95 để thấy aggregation percentiles mà Lens sinh ra.

Checklist Kiến Thức

  • ☐ Kết nối Kibana tới cluster có TLS bằng kibana_system và keystore
  • ☐ Tạo data view với time field đúng
  • ☐ Lọc dữ liệu bằng KQL và filter pill trong Discover
  • ☐ Dựng visualization bằng Lens, dùng Formula và Inspect
  • ☐ Ghép dashboard có control và saved search
  • ☐ Tạo space và role có Kibana privileges
  • ☐ Export và import saved objects qua API

Lỗi Thường Gặp

Những lỗi phổ biến:
  • Kibana đăng nhập bằng user elastic: dùng kibana_system hoặc service account elastic/kibana.
  • Không đặt encryption key: mỗi lần restart sinh key mới, rule và connector đã lưu không giải mã được.
  • Dùng Space để chia dữ liệu giữa khách hàng: người dùng vẫn đọc được index qua API.
  • Dashboard mặc định khoảng 1 năm: mỗi lần mở dashboard tạo tải lớn lên cluster.
  • Sửa dashboard trực tiếp trên production: không có lịch sử thay đổi. Quản lý NDJSON bằng Git.
  • Chọn sai time field trong data view: bộ lọc thời gian cho kết quả lệch hoặc rỗng.

Best Practices & Tài Liệu Tham Khảo

Best Practices

  • Chạy ít nhất 2 instance Kibana sau load balancer cho production, dùng chung encryption key
  • Đặt server.publicBaseUrl để link trong cảnh báo và báo cáo trỏ đúng địa chỉ
  • Mỗi team một space, quyền dữ liệu đặt ở index privileges
  • Lưu saved objects dạng NDJSON trong Git, import tự động khi triển khai
  • Giữ dashboard gọn, khoảng thời gian mặc định ngắn, kiểm tra request bằng Inspect
