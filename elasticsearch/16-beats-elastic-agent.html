Beats & Elastic Agent

Filebeat, Metricbeat, Heartbeat, modules, autodiscover — và vì sao Elastic Agent là hướng đi mới

Nguồn: Elastic — Beats Platform, Elastic — Elastic Agent

Mục Tiêu Học Tập

Sau khi hoàn thành bài này, bạn sẽ: Biết vai trò của từng Beat trong họ Beats. Cấu hình Filebeat đọc log file và container, Metricbeat thu thập metric hệ thống và dịch vụ. Dùng modules và lệnh setup để có sẵn ingest pipeline và dashboard. Bật autodiscover cho môi trường Docker/Kubernetes. Hiểu Elastic Agent khác Beats ở đâu và khi nào chọn cái nào.

Họ Beats

Beats là các agent nhẹ viết bằng Go, mỗi Beat chuyên thu thập một loại dữ liệu và gửi tới Elasticsearch hoặc Logstash.

BeatThu thậpVí dụ
FilebeatLog từ file, container, syslog, Kafka, cloudNginx access log, log ứng dụng, log container
MetricbeatMetric hệ thống và dịch vụCPU, RAM, disk; metric của MySQL, Redis, Kafka, Elasticsearch
HeartbeatKiểm tra uptime chủ độngPing HTTP/TCP/ICMP, đo thời gian phản hồi
PacketbeatLưu lượng mạngGiao dịch HTTP, DNS, MySQL trên đường truyền
AuditbeatSự kiện bảo mật trên hostThay đổi file quan trọng, process, auditd
WinlogbeatWindows Event LogĐăng nhập, lỗi hệ thống trên Windows
Input / Module → Processors → Internal queue → Output (ES / Logstash / Kafka)

Beats xử lý nhẹ tại chỗ bằng processors (thêm metadata, bỏ field, lọc event). Việc bóc tách nặng thường giao cho ingest pipeline trong Elasticsearch.

Filebeat

# filebeat.yml
filebeat.inputs:
  - type: filestream
    id: orders-app-logs              # id bắt buộc, duy nhất cho mỗi filestream input
    paths:
      - /var/log/orders/*.log
    parsers:
      - multiline:                   # gộp stack trace Java thành một event
          type: pattern
          pattern: '^\d{4}-\d{2}-\d{2}'
          negate: true
          match: after
    fields:
      service.name: orders
    fields_under_root: true

processors:
  - add_host_metadata: ~
  - drop_event:
      when:
        contains:
          message: "healthcheck"

output.elasticsearch:
  hosts: ["https://es01:9200"]
  api_key: "${ES_API_KEY}"           # id:api_key
  ssl.certificate_authorities: ["/certs/ca/ca.crt"]

Filebeat đảm bảo không mất log thế nào

  • Registry: Filebeat ghi lại offset đã đọc của từng file. Restart xong đọc tiếp đúng chỗ cũ
  • At-least-once: event chỉ được đánh dấu đã gửi khi output xác nhận. Kết nối lỗi thì gửi lại, nên có thể sinh trùng nhưng không mất
  • Backpressure: khi Elasticsearch chậm, Filebeat đọc chậm lại thay vì dồn bộ nhớ. Log vẫn nằm an toàn trên disk của máy nguồn
  • Log bị xóa hoặc rotate quá nhanh trước khi Filebeat kịp đọc thì vẫn mất. Đây là giới hạn thật cần tính đến khi cấu hình logrotate
filestream thay cho log input Input log cũ đã deprecated. Dùng filestream với id duy nhất. Đổi id của một input đang chạy khiến Filebeat coi đó là input mới và đọc lại file từ đầu.

Metricbeat

# metricbeat.yml
metricbeat.modules:
  - module: system
    metricsets: [cpu, memory, network, filesystem, process]
    period: 10s
    processes: ['.*']

  - module: redis
    metricsets: [info, keyspace]
    hosts: ["redis:6379"]
    period: 10s

  - module: elasticsearch
    xpack.enabled: true               # dùng cho Stack Monitoring (Bài 18)
    hosts: ["https://es01:9200"]
    username: "remote_monitoring_user"
    password: "${MONITORING_PASSWORD}"
    ssl.certificate_authorities: ["/certs/ca/ca.crt"]
    period: 10s

output.elasticsearch:
  hosts: ["https://es01:9200"]
  api_key: "${ES_API_KEY}"
  ssl.certificate_authorities: ["/certs/ca/ca.crt"]

period quyết định độ phân giải và khối lượng dữ liệu. 10 giây cho 100 host với 5 metricset sinh khoảng 4,3 triệu document mỗi ngày. Chọn period theo nhu cầu thật, kết hợp downsampling (Bài 23) cho dữ liệu cũ.

Modules & Setup

Module đóng gói sẵn cách thu thập một nguồn phổ biến: đường dẫn log mặc định, ingest pipeline bóc tách, mapping theo ECS và dashboard Kibana.

# Liệt kê và bật module
filebeat modules list
filebeat modules enable nginx system

# modules.d/nginx.yml
- module: nginx
  access:
    enabled: true
    var.paths: ["/var/log/nginx/access.log*"]
  error:
    enabled: true
# Nạp index template, ILM, ingest pipeline và dashboard vào Elasticsearch/Kibana
filebeat setup -e \
  -E setup.kibana.host=http://kibana:5601 \
  -E output.elasticsearch.username=elastic \
  -E output.elasticsearch.password="${ELASTIC_PASSWORD}"
Quyền cho setup và quyền cho chạy Lệnh setup cần quyền quản trị (tạo template, pipeline, dashboard), nên chạy một lần bằng tài khoản quản trị. Beat chạy thường xuyên chỉ cần API key có quyền ghi dữ liệu. Tách hai loại quyền này để máy nguồn bị xâm nhập không lấy được quyền quản trị cluster.

Autodiscover

Trong Docker và Kubernetes, container sinh ra và mất đi liên tục. Autodiscover theo dõi container runtime và tự bật cấu hình thu thập cho container mới.

# filebeat.yml cho Docker
filebeat.autodiscover:
  providers:
    - type: docker
      hints.enabled: true              # đọc cấu hình từ label của container
      hints.default_config:
        type: container
        paths:
          - /var/lib/docker/containers/${data.container.id}/*.log

processors:
  - add_docker_metadata: ~
# Container tự khai báo cách thu thập log của mình bằng label (hints)
docker run -d \
  --label co.elastic.logs/module=nginx \
  --label co.elastic.logs/fileset.stdout=access \
  --label co.elastic.logs/fileset.stderr=error \
  nginx:1.27

Trên Kubernetes, Filebeat chạy dạng DaemonSet (mỗi node một pod), dùng provider kubernetes và đọc hints từ annotation của pod. Metadata như namespace, pod name, label được gắn tự động vào mỗi log.

Elastic Agent

Elastic Agent là một agent duy nhất thay cho việc cài nhiều Beat riêng lẻ. Một agent thu thập log, metric, uptime, và với Elastic Security còn làm nhiệm vụ endpoint protection.

  • Cấu hình bằng integration (Bài 17) thay vì module, mỗi integration đóng gói input, pipeline, mapping, dashboard
  • Quản lý tập trung qua Fleet: đổi policy trên Kibana, mọi agent nhận cấu hình mới mà không cần đăng nhập từng máy
  • Chạy standalone được nếu không muốn dùng Fleet, với file elastic-agent.yml
  • Gửi dữ liệu vào data stream theo naming scheme type-dataset-namespace (Bài 23)

Bài Lab: Filebeat + Metricbeat Trên Docker

Bước 1: API key cho shipper

source .env
curl $AUTH -X POST "$ES/_security/api_key" -H 'Content-Type: application/json' -d '{
  "name": "beats-lab", "expiration": "7d",
  "role_descriptors": { "beats_writer": {
    "cluster": ["monitor", "read_ilm", "read_pipeline"],
    "indices": [{ "names": ["filebeat-*", "metricbeat-*"], "privileges": ["create_doc", "view_index_metadata", "auto_configure"] }]
  } }
}'
echo "BEATS_API_KEY=<id>:<api_key>" >> .env

Bước 2: Cấu hình

mkdir -p beats
cat > beats/filebeat.yml <<'EOF'
filebeat.autodiscover:
  providers:
    - type: docker
      hints.enabled: true
      hints.default_config:
        type: container
        paths: ["/var/lib/docker/containers/${data.container.id}/*.log"]
processors:
  - add_docker_metadata: ~
output.elasticsearch:
  hosts: ["https://es01:9200"]
  api_key: "${BEATS_API_KEY}"
  ssl.certificate_authorities: ["/certs/ca/ca.crt"]
EOF

cat > beats/metricbeat.yml <<'EOF'
metricbeat.modules:
  - module: system
    metricsets: [cpu, memory, network, process]
    period: 10s
    processes: ['.*']
  - module: docker
    metricsets: [container, cpu, memory]
    hosts: ["unix:///var/run/docker.sock"]
    period: 10s
output.elasticsearch:
  hosts: ["https://es01:9200"]
  api_key: "${BEATS_API_KEY}"
  ssl.certificate_authorities: ["/certs/ca/ca.crt"]
EOF

Bước 3: Thêm vào docker-compose.yml

  filebeat:
    image: docker.elastic.co/beats/filebeat:8.15.0
    user: root
    command: ["--strict.perms=false"]
    environment: [ "BEATS_API_KEY=${BEATS_API_KEY}" ]
    volumes:
      - ./beats/filebeat.yml:/usr/share/filebeat/filebeat.yml:ro
      - ./certs:/certs:ro
      - /var/lib/docker/containers:/var/lib/docker/containers:ro
      - /var/run/docker.sock:/var/run/docker.sock:ro

  metricbeat:
    image: docker.elastic.co/beats/metricbeat:8.15.0
    user: root
    command: ["--strict.perms=false", "-system.hostfs=/hostfs"]
    environment: [ "BEATS_API_KEY=${BEATS_API_KEY}" ]
    volumes:
      - ./beats/metricbeat.yml:/usr/share/metricbeat/metricbeat.yml:ro
      - ./certs:/certs:ro
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - /proc:/hostfs/proc:ro
      - /sys/fs/cgroup:/hostfs/sys/fs/cgroup:ro
      - /:/hostfs:ro
Docker Desktop trên Windows/macOS Đường dẫn /var/lib/docker/containers và /proc nằm trong máy ảo Linux của Docker Desktop, không phải trên máy bạn. Các mount trên vẫn hoạt động vì Docker Desktop ánh xạ chúng vào máy ảo, nhưng metric "system" sẽ là của máy ảo đó. Trên WSL2 hoặc Linux thật, metric phản ánh đúng host.

docker compose up -d filebeat metricbeat
# Sinh log có nhãn nginx
docker run -d --name lab-nginx -p 8080:80 \
  --label co.elastic.logs/module=nginx \

Bước 5: Kiểm tra

curl $AUTH "$ES/_data_stream/filebeat-*,metricbeat-*?filter_path=**.name"
curl $AUTH "$ES/filebeat-*/_count?q=container.name:lab-nginx"
curl $AUTH "$ES/filebeat-*/_search?size=1&q=http.response.status_code:404&filter_path=**._source.url,**._source.http&pretty"

Trong Kibana, mở dashboard "[Filebeat Nginx] Overview ECS" và "[Metricbeat Docker] Overview ECS".

Xác minh thành công Log nginx đã được module bóc tách thành field ECS (http.response.status_code, url.original), mỗi document mang metadata container. Metric CPU/RAM của từng container hiện trên dashboard Metricbeat. Bạn chưa phải viết một dòng grok nào.

Checklist Kiến Thức

  • ☐ Biết vai trò của Filebeat, Metricbeat, Heartbeat, Packetbeat, Auditbeat
  • ☐ Cấu hình filestream input có multiline
  • ☐ Cấu hình Metricbeat module system và một dịch vụ
  • ☐ Bật module và chạy setup
  • ☐ Dùng autodiscover với hints
  • ☐ Gửi dữ liệu qua TLS bằng API key quyền tối thiểu
  • ☐ Giải thích được khi nào chọn Beats, khi nào chọn Elastic Agent

Lỗi Thường Gặp

Những lỗi phổ biến:
  • Không cấu hình multiline: mỗi dòng của stack trace thành một event riêng, không đọc được.
  • Đổi id của filestream input: Filebeat đọc lại toàn bộ file, dữ liệu bị trùng.
  • Beat chạy với user elastic: mỗi máy nguồn giữ một mật khẩu superuser.
  • Bỏ qua lệnh setup: thiếu template và pipeline, log nằm nguyên trong field message.
  • Period quá ngắn cho Metricbeat: khối lượng dữ liệu tăng vọt, chi phí lưu trữ lớn.
  • Beats khác version với Elasticsearch: Beats mới hơn cluster có thể bị từ chối. Giữ Beats ≤ version của Elasticsearch.
