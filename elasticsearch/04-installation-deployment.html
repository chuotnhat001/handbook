Cài Đặt & Triển Khai Elasticsearch

Docker, Docker Compose, Kubernetes (ECK), bare-metal — từ single-node dev đến cluster production

Nguồn: Elastic — Install Elasticsearch, Elastic — ECK

Mục Tiêu Học Tập

Sau khi hoàn thành bài này, bạn sẽ: Triển khai được Elasticsearch bằng Docker single-node, Docker Compose multi-node, Kubernetes (ECK operator) và Linux bare-metal. Nắm các cấu hình bắt buộc (vm.max_map_count, JVM heap). Hiểu cơ chế security bật mặc định từ ES 8.x (TLS tự sinh, enrollment token). Chẩn đoán được các lỗi deploy phổ biến (bootstrap checks).

Kiến Thức Tiên Quyết

  • Bài 03: Kiến Trúc ES — Node roles, cluster, discovery
  • Docker & Docker Compose — image, container, volume, network
  • Linux cơ bản — systemd, sysctl, biến môi trường

Yêu Cầu Hệ Thống

Thành phầnKhuyến nghị
RAMTối thiểu 4GB cho dev; production 32-64GB/node
JVM Heap50% RAM, không quá ~31GB (compressed oops)
DiskSSD/NVMe — Elasticsearch rất nhạy với I/O latency
vm.max_map_countTối thiểu 262144 (bắt buộc, bootstrap check)
File descriptorsTối thiểu 65535
Bootstrap checks Khi chạy ở chế độ production (network.host không phải loopback), ES chuyển bootstrap checks từ warning sang bắt buộc — không đạt là node không khởi động. Đây là cơ chế "bảo vệ bạn khỏi chính mình" trước khi lên production.

Phiên Bản

Elasticsearch dùng versioning theo dòng lớn (major): 7.x, 8.x, 9.x. Dòng 8.x là bản ổn định được dùng rộng rãi, với security bật mặc định. Dòng 9.x là thế hệ mới hơn.

Lưu ý về version Luôn tra version mới nhất tại elastic.co/downloads và pin đúng tag thay vì :latest. Trong bài này tôi dùng ví dụ tag 8.15.0 làm minh họa — thay bằng version thực tế bạn chọn. Elasticsearch, Kibana và các Beats phải cùng major/minor version.

Docker Single-Node

Cách nhanh nhất để chạy thử. Từ ES 8.x, security bật mặc định nên lần đầu chạy sẽ in ra mật khẩu elastic và enrollment token.

# Tạo network riêng
docker network create elastic

# Chạy single-node (thay 8.15.0 bằng version thực tế)
docker run --name es01 --net elastic \
  -p 9200:9200 \
  -e "discovery.type=single-node" \
  -e "ES_JAVA_OPTS=-Xms2g -Xmx2g" \
  -m 4GB \
  docker.elastic.co/elasticsearch/elasticsearch:8.15.0

Lấy mật khẩu & kiểm tra

# Reset mật khẩu user elastic (nếu cần)
docker exec -it es01 bin/elasticsearch-reset-password -u elastic

# Copy CA cert ra ngoài
docker cp es01:/usr/share/elasticsearch/config/certs/http_ca.crt .

# Gọi thử (HTTPS + basic auth)
curl --cacert http_ca.crt -u elastic https://localhost:9200
Dev nhanh, không TLS Nếu chỉ học và muốn bỏ qua security cho đơn giản, thêm -e "xpack.security.enabled=false". Tuyệt đối không làm vậy ở production.

Docker Compose Multi-Node

Dựng cluster 3 node để học về shard/replica thật. File docker-compose.yml rút gọn:

services:
  es01:
    image: docker.elastic.co/elasticsearch/elasticsearch:8.15.0
    environment:
      - node.name=es01
      - cluster.name=es-docker-cluster
      - discovery.seed_hosts=es02,es03
      - cluster.initial_master_nodes=es01,es02,es03
      - xpack.security.enabled=false
      - bootstrap.memory_lock=true
      - "ES_JAVA_OPTS=-Xms2g -Xmx2g"
    ulimits:
      memlock: { soft: -1, hard: -1 }
    volumes: [ "data01:/usr/share/elasticsearch/data" ]
    ports: [ "9200:9200" ]

  es02:
    image: docker.elastic.co/elasticsearch/elasticsearch:8.15.0
    environment:
      - node.name=es02
      - cluster.name=es-docker-cluster
      - discovery.seed_hosts=es01,es03
      - cluster.initial_master_nodes=es01,es02,es03
      - xpack.security.enabled=false
      - "ES_JAVA_OPTS=-Xms2g -Xmx2g"
    volumes: [ "data02:/usr/share/elasticsearch/data" ]

  es03:
    image: docker.elastic.co/elasticsearch/elasticsearch:8.15.0
    environment:
      - node.name=es03
      - cluster.name=es-docker-cluster
      - discovery.seed_hosts=es01,es02
      - cluster.initial_master_nodes=es01,es02,es03
      - xpack.security.enabled=false
      - "ES_JAVA_OPTS=-Xms2g -Xmx2g"
    volumes: [ "data03:/usr/share/elasticsearch/data" ]

volumes:
  data01: {}
  data02: {}
  data03: {}
docker compose up -d
docker compose ps
# Kiểm tra cluster hình thành
curl "http://localhost:9200/_cat/nodes?v"
Vì sao file này tắt security Khi node có cấu hình discovery (multi-node), ES 8.x không tự sinh certificate. Nếu để security bật mà chưa cấu hình transport TLS, bootstrap check sẽ chặn node khởi động. File trên tắt security để dựng lab nhanh và chỉ dùng cho lab cục bộ. Cluster multi-node có security cần sinh certificate trước, xem file compose chính thức trong tài liệu Elastic "Install Elasticsearch with Docker" (dùng một container setup chạy elasticsearch-certutil).
Nhắc lại từ Bài 03 cluster.initial_master_nodes chỉ dùng lúc bootstrap lần đầu. Sau khi cluster đã hình thành, nên gỡ bỏ để tránh rắc rối khi restart.

Kubernetes — ECK Operator

ECK (Elastic Cloud on Kubernetes) là operator chính thức, quản lý vòng đời ES/Kibana trên K8s qua Custom Resource Definitions (CRD).

# Cài CRDs và operator
kubectl create -f https://download.elastic.co/downloads/eck/2.14.0/crds.yaml
kubectl apply -f https://download.elastic.co/downloads/eck/2.14.0/operator.yaml

# Khai báo một cluster 3 node bằng CRD
cat <<EOF | kubectl apply -f -
apiVersion: elasticsearch.k8s.elastic.co/v1
kind: Elasticsearch
metadata:
  name: quickstart
spec:
  version: 8.15.0
  nodeSets:
  - name: default
    count: 3
    config:
      node.store.allow_mmap: false
EOF

# Lấy mật khẩu elastic do operator tự sinh
kubectl get secret quickstart-es-elastic-user \
  -o go-template='{{.data.elastic | base64decode}}'

Ngoài ECK, có thể dùng Helm chart chính thức của Elastic cho các setup tùy biến hơn. ECK được khuyến nghị vì tự động hóa TLS, rolling upgrade, và scaling.

Linux Bare-Metal (systemd)

# 1. Cài qua package (Debian/Ubuntu) — thêm repo Elastic trước
sudo apt-get install elasticsearch

# 2. Cấu hình bắt buộc trên host
sudo sysctl -w vm.max_map_count=262144
echo "vm.max_map_count=262144" | sudo tee -a /etc/sysctl.conf

# 3. Bật và khởi động service
sudo systemctl daemon-reload
sudo systemctl enable elasticsearch.service
sudo systemctl start elasticsearch.service

# 4. Mật khẩu elastic in ra khi cài, hoặc reset:
sudo /usr/share/elasticsearch/bin/elasticsearch-reset-password -u elastic

Cũng có thể cài từ bản archive (tar.gz/zip) — giải nén, chạy bin/elasticsearch; phù hợp khi không có quyền root hoặc cần nhiều instance trên một host.

Cấu Hình elasticsearch.yml

# config/elasticsearch.yml
cluster.name: my-production-cluster
node.name: node-1
node.roles: [ master, data ]

# Network — đặt IP thật để các node thấy nhau (kích hoạt production mode)
network.host: 10.0.0.1
http.port: 9200

# Discovery
discovery.seed_hosts: ["10.0.0.1", "10.0.0.2", "10.0.0.3"]
cluster.initial_master_nodes: ["node-1", "node-2", "node-3"]

# Data & log path
path.data: /var/lib/elasticsearch
path.logs: /var/log/elasticsearch

JVM heap đặt trong config/jvm.options hoặc file trong jvm.options.d/:

# jvm.options.d/heap.options
-Xms16g
-Xmx16g
# Quy tắc: Xms = Xmx, = 50% RAM, không quá ~31GB

Security Mặc Định (ES 8.x+)

Từ ES 8.0, khi khởi động lần đầu Elasticsearch tự động:

  • Sinh TLS certificates — mã hóa cả HTTP layer và inter-node transport
  • Tạo mật khẩu ngẫu nhiên cho user elastic (in ra console/log một lần duy nhất)
  • Sinh enrollment token — dùng để Kibana hoặc node mới join cluster an toàn
# Sinh enrollment token cho Kibana
bin/elasticsearch-create-enrollment-token -s kibana

# Sinh token cho node mới join cluster
bin/elasticsearch-create-enrollment-token -s node
Tư duy cốt lõi ES 8.x biến "secure by default" thành mặc định: không còn chuyện vô tình để cluster mở toang ra internet không mật khẩu. Chi tiết TLS/RBAC xem Bài 13.

Bài Lab: Triển Khai Cluster 3 Node Trên Docker Compose

Mục tiêu

Dựng cluster 3 node, xác minh nó hình thành đúng, index thử dữ liệu và quan sát shard phân bổ.

Bước 1: Chuẩn bị host

# Linux/WSL2
sudo sysctl -w vm.max_map_count=262144
# macOS Docker Desktop: đặt trong Settings → Resources (RAM ≥ 6GB)

Bước 2: Khởi động bằng file compose ở trên

docker compose up -d
# Chờ ~30-60s cho cluster hình thành
docker compose logs -f es01 | grep -i "started"

Bước 3: Xác minh cluster

curl "http://localhost:9200/_cluster/health?pretty"
# Mong đợi: "number_of_nodes": 3, "status": "green"

curl "http://localhost:9200/_cat/nodes?v&h=name,node.role,master"

Bước 4: Index thử và quan sát shard

curl -X PUT "http://localhost:9200/lab-deploy" \
  -H 'Content-Type: application/json' \
  -d '{"settings":{"number_of_shards":3,"number_of_replicas":1}}'

curl "http://localhost:9200/_cat/shards/lab-deploy?v"
# 3 primary + 3 replica trải trên 3 node, primary ≠ replica node
Xác minh thành công Cluster health green, 3 node, shard phân bổ hợp lý (primary và replica không cùng node). Bạn giờ có một môi trường lab thật để dùng cho các bài sau.

  4. ES 8.x tự động làm gì về security khi khởi động lần đầu?

Checklist Kiến Thức

  • ☐ Triển khai được single-node bằng Docker
  • ☐ Dựng được cluster 3 node bằng Docker Compose

Lỗi Thường Gặp

Những lỗi deploy phổ biến:
  • Quên vm.max_map_count — Node crash với "max virtual memory areas vm.max_map_count [65530] is too low". Fix bằng sysctl.
  • Heap quá lớn (>31GB) — Mất compressed ordinary object pointers → lãng phí RAM, GC chậm hơn. Giữ dưới 31GB.
  • Dùng tag :latest — Deploy không reproducible, dễ lệch version giữa các node. Luôn pin version cụ thể.
  • Để initial_master_nodes mãi mãi — Chỉ dùng lúc bootstrap. Giữ lại gây rắc rối khi cluster đã hình thành.
  • Tắt security ở production — xpack.security.enabled=false chỉ cho dev cục bộ. Production để mở là mời gọi tấn công/ransomware.
  • Không đặt memlock / swap — Để OS swap heap của ES ra disk làm performance sụp đổ. Dùng bootstrap.memory_lock=true.

Best Practices & Tài Liệu Tham Khảo

Best Practices

  • Dev/học: Docker single-node hoặc Compose 3 node. Production: ECK trên K8s hoặc bare-metal có cấu hình kỹ
  • Pin version chính xác, giữ ES/Kibana/Beats đồng bộ version
  • JVM heap = 50% RAM, ≤ 31GB; bật bootstrap.memory_lock, tắt swap
  • Đặt vm.max_map_count=262144 vĩnh viễn qua /etc/sysctl.conf
  • Giữ security bật; quản lý secret qua keystore (bin/elasticsearch-keystore), không hardcode
  • Dùng dedicated volume/SSD cho path.data, tách khỏi OS disk
