Text Analysis & Tokenization

Character filter, tokenizer, token filter — cách Elasticsearch biến text thành terms có thể tìm kiếm

Nguồn: Elastic — Text Analysis, Elastic — ICU Analysis Plugin

Mục Tiêu Học Tập

Sau khi hoàn thành bài này, bạn sẽ: Hiểu analyzer gồm 3 thành phần: character filter, tokenizer, token filter. Dùng được các built-in analyzer và tự xây custom analyzer. Phân biệt index-time và search-time analyzer. Biết các lựa chọn xử lý tiếng Việt (ICU, asciifolding, plugin cộng đồng). Debug tokenization bằng _analyze API.

Kiến Thức Tiên Quyết

  • Bài 02: Lucene — Inverted index lưu terms
  • Bài 06: Mapping — Field text được analyze, keyword thì không

Pipeline Phân Tích

Analysis (phân tích) là quá trình biến text thô thành danh sách terms lưu vào inverted index. Một analyzer chạy 3 bước theo thứ tự:

Text thô → Character Filters (0..n) → Tokenizer (đúng 1) → Token Filters (0..n) → Terms 
Input:  "<p>Elasticsearch là Search Engine!</p>"
Char filter (html_strip):  "Elasticsearch là Search Engine!"
Tokenizer (standard):      ["Elasticsearch", "là", "Search", "Engine"]
Token filter (lowercase):  ["elasticsearch", "là", "search", "engine"]
Tư duy cốt lõi Search chỉ khớp khi terms lúc query trùng với terms lúc index. Hầu hết lỗi "tìm không ra" đều do analyzer lúc index và lúc search xử lý text khác nhau. Luôn kiểm tra bằng _analyze.

Character Filters

Xử lý chuỗi ký tự trước khi tách token:

FilterTác dụng
html_stripBỏ thẻ HTML, decode entity (&amp; → &)
mappingThay thế ký tự theo bảng (vd :) → _happy_)
pattern_replaceThay thế theo regex

Tokenizers

Tách chuỗi thành các token. Mỗi analyzer có đúng một tokenizer.

TokenizerCách táchVí dụ "Wi-Fi 6E router"
standardTheo Unicode Text Segmentation (UAX #29)[Wi, Fi, 6E, router]
whitespaceChỉ theo khoảng trắng[Wi-Fi, 6E, router]
keywordKhông tách — giữ nguyên chuỗi[Wi-Fi 6E router]
patternTheo regextùy pattern
ngram / edge_ngramCắt thành các mảnh n ký tựedge_ngram: [r, ro, rou...]
icu_tokenizerTừ ICU plugin — xử lý tốt ngôn ngữ châu Á—

Token Filters

Biến đổi, thêm hoặc bỏ token sau khi tách:

FilterTác dụng
lowercaseChuyển chữ thường
stopBỏ stop words ("the", "a", "là", "của"...)
stemmerĐưa về gốc từ ("running" → "run") — chủ yếu ngôn ngữ biến hình như tiếng Anh
synonym / synonym_graphThêm từ đồng nghĩa ("laptop" ↔ "máy tính xách tay")
asciifoldingBỏ dấu ("điện thoại" → "dien thoai")
edge_ngramSinh prefix cho autocomplete

Built-in Analyzers

AnalyzerThành phần
standard (mặc định)standard tokenizer + lowercase
simpleTách ở ký tự không phải chữ + lowercase
whitespaceTách theo khoảng trắng, không lowercase
keywordKhông phân tích (giống field keyword)
english, french...Language analyzer: stop words + stemming theo ngôn ngữ
POST _analyze
{ "analyzer": "english", "text": "The foxes are running quickly" }
# → ["fox", "run", "quickli"]  (stop words bị bỏ, stemming)

Custom Analyzer

PUT /articles
{
  "settings": {
    "analysis": {
      "char_filter": {
        "emoticons": { "type": "mapping", "mappings": [":) => _happy_", ":( => _sad_"] }
      },
      "filter": {
        "my_synonyms": { "type": "synonym_graph", "synonyms": ["laptop, notebook, máy tính xách tay"] }
      },
      "analyzer": {
        "my_analyzer": {
          "type": "custom",
          "char_filter": ["html_strip", "emoticons"],
          "tokenizer": "standard",
          "filter": ["lowercase", "asciifolding"]
        },
        "my_search_analyzer": {
          "type": "custom",
          "tokenizer": "standard",
          "filter": ["lowercase", "asciifolding", "my_synonyms"]
        }
      }
    }
  },
  "mappings": {
    "properties": {
      "body": { "type": "text", "analyzer": "my_analyzer", "search_analyzer": "my_search_analyzer" }
    }
  }
}
Analyzer gắn với index Analyzer định nghĩa trong settings.analysis của index. Đổi analyzer của field đã có dữ liệu cần reindex (terms cũ đã nằm trong inverted index). Riêng synonym dùng ở search-time có thể cập nhật linh hoạt hơn (reload search analyzer).

Index-time vs Search-time Analyzer

  • analyzer — dùng khi index (và khi search nếu không khai báo gì khác)
  • search_analyzer — dùng riêng lúc query

Trường hợp điển hình: autocomplete. Lúc index dùng edge_ngram để sinh prefix ("lap" → [l, la, lap]), nhưng lúc search không ngram query (nếu không, gõ "lap" sẽ khớp mọi thứ bắt đầu bằng "l").

"analysis": {
  "filter": { "autocomplete_filter": { "type": "edge_ngram", "min_gram": 2, "max_gram": 15 } },
  "analyzer": {
    "autocomplete": { "tokenizer": "standard", "filter": ["lowercase", "autocomplete_filter"] }
  }
}
# mapping:
"name": { "type": "text", "analyzer": "autocomplete", "search_analyzer": "standard" }

Xử Lý Tiếng Việt

Elasticsearch không có language analyzer tiếng Việt chính thức. Thách thức: tiếng Việt là ngôn ngữ đơn lập, một từ có thể gồm nhiều âm tiết cách nhau bởi khoảng trắng ("máy tính", "điện thoại") nên tách theo khoảng trắng sẽ cắt rời từ ghép.

Cách tiếp cậnƯuNhược
standard + lowercaseCó sẵn, đơn giảnTách theo âm tiết, mất nghĩa từ ghép
+ asciifolding (preserve_original)Người dùng gõ không dấu vẫn tìm đượcTăng nhập nhằng ("ban" = bàn/bán/bạn)
icu_tokenizer + icu_folding (ICU plugin)Chuẩn hóa Unicode tốt (NFC/NFD), plugin chính thứcVẫn chủ yếu tách theo âm tiết
Plugin cộng đồng (word segmentation)Tách từ ghép theo từ điểnPhụ thuộc bên thứ ba, phải khớp version ES
Kết hợp shingle (bigram)Ghép âm tiết liền kề → xấp xỉ từ ghép, tăng độ chính xác phraseIndex lớn hơn
# Cài ICU plugin (mỗi node, rồi restart)
bin/elasticsearch-plugin install analysis-icu

PUT /vn-products
{
  "settings": { "analysis": {
    "filter": {
      "vn_folding": { "type": "asciifolding", "preserve_original": true },
      "vn_shingle": { "type": "shingle", "min_shingle_size": 2, "max_shingle_size": 2 }
    },
    "analyzer": {
      "vietnamese": {
        "tokenizer": "icu_tokenizer",
        "filter": ["icu_normalizer", "lowercase", "vn_folding"]
      },
      "vietnamese_shingle": {
        "tokenizer": "icu_tokenizer",
        "filter": ["icu_normalizer", "lowercase", "vn_shingle"]
      }
    }
  }},
  "mappings": { "properties": {
    "name": { "type": "text", "analyzer": "vietnamese",
              "fields": { "phrase": { "type": "text", "analyzer": "vietnamese_shingle" } } }
  }}
}
Chuẩn hóa Unicode quan trọng Cùng chữ "ệ" có thể được mã hóa dạng dựng sẵn (NFC) hoặc tổ hợp (NFD) tùy nguồn nhập. Không chuẩn hóa → hai chuỗi trông giống hệt nhau nhưng không khớp. icu_normalizer giải quyết việc này.
Plugin cộng đồng Có các plugin tách từ tiếng Việt do cộng đồng phát triển. Trước khi dùng ở production, kiểm tra plugin còn được bảo trì và có bản build khớp đúng version Elasticsearch của bạn — plugin phải khớp version chính xác mới cài được.

Bài Lab: Analyzer Cho Tiếng Việt

Bước 1: So sánh tokenizer có sẵn

POST _analyze
{ "analyzer": "standard", "text": "Điện thoại thông minh giá rẻ" }

POST _analyze
{ "tokenizer": "standard", "filter": ["lowercase", "asciifolding"],
  "text": "Điện thoại thông minh giá rẻ" }
# → ["dien", "thoai", "thong", "minh", "gia", "re"]

Bước 2: Tạo index với analyzer tiếng Việt

Dùng định nghĩa vn-products ở trên (cần ICU plugin). Nếu chưa cài plugin, thay icu_tokenizer bằng standard và bỏ icu_normalizer.

Bước 3: Test analyzer trên index

POST /vn-products/_analyze
{ "analyzer": "vietnamese", "text": "Máy tính xách tay" }
# preserve_original → giữ cả "máy" và "may"

POST /vn-products/_analyze
{ "analyzer": "vietnamese_shingle", "text": "Máy tính xách tay" }
# → ["máy tính", "tính xách", "xách tay"]

Bước 4: Index và search có dấu / không dấu

POST /vn-products/_doc
{ "name": "Điện thoại Samsung Galaxy" }
POST /vn-products/_refresh

GET /vn-products/_search
{ "query": { "match": { "name": "dien thoai" } } }
# Tìm thấy dù gõ không dấu

GET /vn-products/_search
{ "query": { "match": { "name.phrase": "điện thoại" } } }
# Khớp chính xác cụm từ ghép
Xác minh thành công Người dùng gõ có dấu hoặc không dấu đều tìm được sản phẩm, và sub-field shingle giúp ưu tiên khớp từ ghép. Đây là cấu hình nền tảng cho search tiếng Việt.

Câu Hỏi Ôn Tập

  1. Analyzer gồm những thành phần nào và chạy theo thứ tự nào? Mỗi analyzer có bao nhiêu tokenizer?
  2. Vì sao "tìm không ra" thường do analyzer? Dùng công cụ gì để debug?
  3. Khác biệt giữa standard, whitespace, keyword tokenizer?
  4. Khi nào cần search_analyzer khác analyzer? Cho ví dụ autocomplete.
  5. Vì sao tiếng Việt khó cho tokenizer mặc định? Nêu 3 cách tiếp cận.
  6. asciifolding với preserve_original giúp gì và đánh đổi gì?
  7. Vì sao đổi analyzer của field đã có dữ liệu phải reindex?

Checklist Kiến Thức

  • ☐ Mô tả pipeline char filter → tokenizer → token filter
  • ☐ Biết các tokenizer và token filter phổ biến
  • ☐ Dùng built-in và language analyzer
  • ☐ Viết được custom analyzer trong index settings
  • ☐ Phân biệt analyzer và search_analyzer
  • ☐ Cấu hình search tiếng Việt có dấu / không dấu
  • ☐ Debug bằng _analyze API

Lỗi Thường Gặp

Những lỗi phổ biến:
  • Không test bằng _analyze trước khi index — Phát hiện analyzer sai sau khi đã index hàng triệu doc → phải reindex.
  • Dùng edge_ngram cả lúc search — Kết quả autocomplete nhiễu. Chỉ ngram lúc index.
  • Bỏ dấu hoàn toàn (không preserve_original) — Mất khả năng ưu tiên kết quả đúng dấu; "bán" và "bạn" thành một.
  • Quên chuẩn hóa Unicode — Text NFC và NFD không khớp nhau dù hiển thị giống hệt.
  • Stemmer tiếng Anh cho tiếng Việt — Vô nghĩa, có thể làm sai term. Tiếng Việt không biến hình.
  • Synonym quá rộng ở index-time — Khó cập nhật (phải reindex). Ưu tiên synonym ở search-time.

Best Practices & Tài Liệu Tham Khảo

Best Practices

  • Luôn thử analyzer bằng _analyze với dữ liệu thật trước khi tạo index
  • Dùng multi-field để phục vụ nhiều kiểu search (exact, không dấu, phrase) cho cùng dữ liệu
  • Đặt synonym ở search-time để cập nhật không cần reindex
  • Tiếng Việt: chuẩn hóa Unicode + lowercase + asciifolding (preserve_original), cân nhắc shingle cho từ ghép
  • Autocomplete: edge_ngram ở index-time, standard ở search-time (hoặc dùng field search_as_you_type)
  • Pin version plugin phân tích khớp với version Elasticsearch
