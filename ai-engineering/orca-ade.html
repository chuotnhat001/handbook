Orca — Agent Development Environment

Môi trường phát triển để chạy nhiều AI coding agents song song trong các worktrees cách ly (isolated)

Nguồn: orca.build — Free MIT License — backed by Y Combinator (sản phẩm có trang chủ riêng, không công bố repo GitHub công khai tại 23/10/2026)
Tư duy cốt lõi Orca là ADE (Agent Development Environment — Môi trường Phát triển Agent), không phải IDE. Triết lý: con người giám sát (supervise), agents thực thi (execute). Mỗi task chạy trong git worktree cách ly (isolated) riêng — nhiều agents làm việc song song trên cùng repo mà không xung đột (conflict) với nhau.

Orca cho phép bạn khởi tạo (spawn) nhiều coding agents đồng thời, mỗi agent hoạt động trong môi trường cách ly (isolated environment). Tập trung terminals, diffs (so sánh thay đổi), browser windows và CLI tooling vào một môi trường duy nhất. Bạn mang API keys và gói đăng ký (subscriptions) của mình — Orca không bán lại (resell) tokens.

Orca giải quyết vấn đề gì?

Khi dùng AI coding agents (Claude Code, Codex...) trong terminal hoặc IDE thông thường:

  • Xung đột files (Conflict) — Chạy 2 agents cùng lúc trên 1 repo = chúng ghi đè (overwrite) files của nhau
  • Chuyển đổi ngữ cảnh (Context switching) — Phải mở nhiều terminal tabs, browser tabs, theo dõi thủ công
  • Không so sánh được — Muốn thử 3 cách giải quyết khác nhau? Phải làm tuần tự
  • Vòng phản hồi frontend chậm (Feedback loop) — Copy-paste screenshots, mô tả UI bằng text

Orca giải quyết bằng cách cho mỗi agent một git worktree cách ly (isolated) — như có 5 bản sao của repo chạy song song, nhưng chia sẻ chung (share) git history.

Mỗi worktree cần dung lượng đĩa (disk space) riêng cho các thư viện phụ thuộc (dependencies) như node_modules, venv, v.v. Nếu project của bạn có 500MB dependencies, chạy 5 agents = 2.5GB disk.

Khuyến nghị Với 8GB RAM, chạy thoải mái 2-3 agents. Nếu muốn chạy 5 agents, nên dùng SSH worktrees để chuyển tải (offload) sang máy chủ từ xa (remote server) hoặc có ít nhất 16GB RAM.

Phần mềm yêu cầu

  • Git — Orca dựa trên git worktrees, cần Git 2.20+
  • CLI agents — Cài sẵn agents bạn muốn dùng (Claude Code, Codex, etc.)
  • API keys — Chuẩn bị sẵn API keys hoặc subscriptions

Giao diện Orca

Khi mở Orca lần đầu, bạn sẽ thấy giao diện chia làm 3 phần chính:

1. Thanh bên trái (Left Sidebar) — Danh sách Worktree

Hiển thị tất cả worktrees đang hoạt động (active) với chỉ báo trạng thái (status indicators):

  • Màu xanh — Agent đang chạy (running)
  • Màu vàng — Có thay đổi (changes) chưa xem xét (review)
  • Màu xám — Rảnh (Idle), chờ nhập liệu (input)

Click vào worktree để tập trung (focus), double-click để đổi tên (rename).

2. Khung giữa (Center Pane) — Trình soạn thảo mã (Code Editor)

Monaco editor (cùng engine với VS Code) với:

  • Tô màu cú pháp (Syntax highlighting) cho 100+ ngôn ngữ
  • Tự động lưu (Autosave)
  • Hỗ trợ kéo thả file (Drag-drop)
  • Xem trước Markdown và PDF (Preview)
  • Chế độ xem khác biệt (Diff view) cho các thay đổi

3. Khung bên phải (Right Panel) — Terminals

Terminal render bằng GPU (Ghostty-class WebGL) với:

  • Chia vô hạn (Infinite splits) — Chia terminal theo chiều ngang/dọc tùy ý
  • Lịch sử cuộn lưu trữ (Persistent scrollback) — Cuộn lại xem output cũ, giữ qua khởi động lại (survive restarts)
  • Tìm kiếm (Search) — Tìm text trong lịch sử cuộn (scrollback)

4. Thanh dưới (Bottom Bar) — Hành động (Actions)

  • New Worktree — Tạo worktree mới
  • Design Mode — Bật browser cho frontend work
  • Diff View — Xem changes của worktree hiện tại

Dự án đầu tiên — Hướng dẫn từng bước

Tutorial này sẽ hướng dẫn bạn setup Orca với một project có sẵn và chạy agent đầu tiên.

Bước 1: Chuẩn bị project

Đảm bảo bạn có một git repository trên máy. Nếu chưa có:

# Clone một project để thử
git clone https://github.com/your-username/your-project.git
cd your-project

Bước 2: Mở Orca và Add Repository

  1. Mở Orca
  2. Click "Add Repository" hoặc drag folder vào cửa sổ
  3. Chọn folder chứa git repository
  4. Orca sẽ detect default branch (thường là main hoặc master)

Bước 3: Configure Agent

  1. Click Settings (gear icon)
  2. Vào tab Agents
  3. Orca tự động detect agents đã cài. Nếu thấy agent bạn muốn dùng, click để configure
  4. Nhập API key hoặc authenticate (tùy agent)
  5. Click Test Connection để verify
Ví dụ: Configure Claude Code Nếu bạn đã cài Claude Code CLI (claude command), Orca sẽ tự detect. Click vào Claude Code, nhập Anthropic API key hoặc login với Claude Pro account.

Bước 4: Tạo Worktree đầu tiên

  1. Click "New Worktree"
  2. Đặt tên mô tả task: fix-login-bug
  3. Chọn agent: Claude Code (hoặc agent bạn đã configure)
  4. Click Create

Orca sẽ tạo một git worktree mới trong .orca/worktrees/fix-login-bug/. Đây là bản copy isolated của repo — agent có thể edit files mà không ảnh hưởng main branch.

Bước 5: Chạy Agent

  1. Trong terminal của worktree, bạn sẽ thấy agent prompt
  2. Gõ task description:
Fix the login bug where users get "Invalid credentials" even with correct password.
The issue is in src/auth/login.ts
  1. Nhấn Enter và để agent làm việc
  2. Agent sẽ read files, analyze, và propose changes

Bước 6: Review và Merge

  1. Khi agent hoàn thành, click Diff View để xem changes
  2. Review từng file. Nếu cần feedback, dùng Diff Annotation (click vào line và comment)
  3. Nếu satisfied, click Commit
  4. Click Merge to main để merge changes vào main branch
  5. Hoặc click Delete Worktree nếu không muốn giữ changes
Xong! Bạn vừa hoàn thành workflow cơ bản: Create worktree → Run agent → Review → Merge. Giờ bạn có thể thử tạo nhiều worktrees với cùng prompt và so sánh outputs.

Parallel Worktrees — Core Primitive

Git worktrees là tính năng cho phép một repo có nhiều branches được checkout (lấy ra) đồng thời trong các folders riêng biệt, nhưng vẫn chia sẻ chung (share) git history. Orca dùng cơ chế này làm nền tảng (foundation).

Worktree là gì?

Bình thường khi bạn có một git repo, bạn chỉ có thể checkout 1 branch tại 1 thời điểm. Nếu muốn làm việc trên branch khác, phải lưu tạm thay đổi (stash changes), chuyển branch (switch), rồi chuyển lại.

Với worktrees, bạn có thể có:

my-project/              ← main branch (original)
my-project-worktree-1/   ← feature-a branch
my-project-worktree-2/   ← feature-b branch
my-project-worktree-3/   ← bugfix branch

Tất cả share cùng .git history, nhưng mỗi cái là một folder riêng với branch riêng. Changes trong worktree-1 không ảnh hưởng worktree-2.

Lợi ích cho AI agents Mỗi agent có "hộp cát (sandbox)" riêng. Claude Code sửa files trong worktree-1, Codex sửa files trong worktree-2 — không xung đột (conflict), không ghi đè (overwrite) nhau. Bạn có thể chạy song song rồi so sánh kết quả.

Tạo và quản lý worktrees trong Orca

Tạo worktree mới

# Cách 1: Trong Orca UI
Click "New Worktree" → Đặt tên → Chọn agent → Create

# Cách 2: Dùng CLI
orca worktree create --name "feature-auth"
orca worktree create --name "bugfix-login" --agent "claude-code"

List worktrees

orca worktree list

# Output:
# NAME              BRANCH                    AGENT        STATUS
# feature-auth      feature-auth-2024-03-15   claude-code  running
# bugfix-login      bugfix-login-2024-03-15   codex        idle

Delete worktree

# Sau khi merge hoặc discard
orca worktree delete feature-auth

# Xóa tất cả worktrees đã merge
orca worktree prune

Workflow hoàn chỉnh với worktrees

Create worktree → Run agent → Review diff → Annotate/Iterate → Merge/Discard

Design Mode

Mỗi worktree có một embedded Chromium window riêng. Design Mode biến nó thành công cụ để giao tiếp với agent về frontend.

Vấn đề Design Mode giải quyết

Khi mô tả UI cho AI agent:

  • Không có Design Mode: "Fix the button in the header, the one on the right side, it's blue, the hover state is wrong..."
  • Có Design Mode: Click vào button → Agent nhận được HTML, CSS, và screenshot chính xác

Cách sử dụng Design Mode

Bước 1: Bật Design Mode

  1. Trong worktree, click Design Mode button (hoặc phím tắt)
  2. Chromium window sẽ mở với app của bạn
  3. Navigate đến page cần edit

Bước 2: Chọn element

  1. Click vào UI element cần sửa (button, card, form...)
  2. Orca highlights element và hiển thị selector
  3. Bạn có thể chọn parent element bằng cách click lại hoặc dùng keyboard navigation

Bước 3: Gửi đến agent

  1. Click Send to Agent
  2. Orca package và gửi cho agent:
    • HTML của element (và parent context)
    • Computed CSS styles
    • Cropped screenshot của element
    • Full page screenshot (optional)
  3. Viết instruction: "Make this button larger and change hover color to blue"

Bước 4: Xem kết quả

  1. Agent sửa code trong worktree
  2. Browser auto-refresh (nếu có HMR/hot reload)
  3. Nếu chưa ưng, click element → annotate → gửi lại
Tip: Kết hợp với Diff Annotation Sau khi agent sửa CSS, review diff. Nếu có line không đúng, annotate trực tiếp trên diff thay vì mô tả lại. Tiết kiệm tokens và chính xác hơn.

Diff Annotation

Thay vì nhắc lại toàn bộ (re-prompt) khi agent sửa không đúng, bạn có thể bình luận trực tiếp trên dòng code (comment inline) trên các diffs (bản so sánh thay đổi).

Tại sao Diff Annotation hiệu quả?

  • Chính xác — Chỉ đến đúng dòng (exact line), không cần mô tả "the line where you added X"
  • Tiết kiệm tokens — Không cần lặp lại ngữ cảnh (repeat context), chỉ gửi phần thay đổi (delta)
  • Gộp phản hồi (Batch feedback) — Ghi chú 10 dòng rồi gửi 1 lần, thay vì 10 lần nhắc lại

Cách dùng

Bước 1: Mở Diff View

Sau khi agent hoàn thành, click Diff View để xem changes.

Bước 2: Annotate lines

  1. Click vào line number cần feedback
  2. Popup xuất hiện — viết comment bằng markdown
  3. Ví dụ comments: 
    Use async/await instead of .then() chain

---

This will cause a memory leak - need to cleanup in useEffect return

---

Rename to `handleUserLogin` to match our naming convention
  4. Click Add Comment

Bước 3: Review và gửi

  1. Tiếp tục annotate các lines khác
  2. Review tất cả annotations trong sidebar
  3. Click Send Feedback
  4. Agent sẽ nhận annotations và refine code

Thực hành tốt khi ghi chú (Annotation best practices)

  • Cụ thể (Be specific) — "Use map instead of forEach" thay vì "This is wrong"
  • Giải thích lý do (Explain why) — "This mutates state directly, React won't re-render" giúp agent học được mẫu (pattern)
  • Gộp các ghi chú liên quan (Batch related) — Đừng gửi từng annotation một

Remote SSH Worktrees — Worktree trên máy chủ từ xa

Chạy agents trên máy từ xa (remote machines) khi:

  • Máy cục bộ (local machine) không đủ RAM cho nhiều agents
  • Cần môi trường phát triển khác (Linux server, thư viện phụ thuộc cụ thể)
  • Muốn chạy tác vụ dài (long-running tasks) không bị ảnh hưởng bởi laptop ngủ (sleep)

Setup SSH Worktree

Bước 1: Configure SSH trong Orca

  1. Settings → SSH → Add Remote
  2. Nhập connection details: 
    Host: dev-server.company.com
User: your-username
Port: 22 (default)
Identity File: ~/.ssh/id_rsa (hoặc chọn key)
  3. Click Test Connection

Bước 2: Clone repo trên remote

Đảm bảo repo đã được clone trên remote server:

ssh dev-server
cd /home/your-username/projects
git clone git@github.com:your-org/your-project.git

Bước 3: Tạo Remote Worktree trong Orca

  1. New Worktree → Toggle Remote
  2. Chọn SSH remote đã configure
  3. Chọn repo path trên remote
  4. Đặt tên và chọn agent
  5. Create

Tính năng của Remote Worktrees

  • Chỉnh sửa file đầy đủ (Full file editing) — Sửa files như trên máy cục bộ, Orca đồng bộ qua SSH
  • Thao tác Git (Git operations) — Commit, push, merge từ Orca UI
  • Truy cập Terminal — Terminal chạy trên máy từ xa
  • Tự động kết nối lại (Auto-reconnect) — Nếu kết nối bị ngắt (connection drop), Orca tự kết nối lại
  • Chuyển tiếp cổng (Port forwarding) — Chuyển tiếp ports để test trên máy cục bộ (e.g., localhost:3000 → remote:3000)
  • Lưu mật khẩu (Passphrase caching) — Không cần nhập passphrase mỗi lần
Recommendation Với 8GB RAM local, chạy 1-2 agents local và 2-3 agents remote. Orca handles coordination seamlessly.

  2. Scan QR code bằng mobile app

Orca CLI

Full CLI để control Orca từ terminal, enabling scripting và automation.

Worktree Commands

# Tạo worktree
orca worktree create --name "task-name" --agent "claude-code"

# List worktrees
orca worktree list

# Delete worktree
orca worktree delete "task-name"

# Prune merged worktrees
orca worktree prune

Agent Commands

# Send prompt to agent in worktree
orca agent send "task-name" "Fix the login bug in auth.ts"

# Check agent status
orca agent status "task-name"

# Stop running agent
orca agent stop "task-name"

Utility Commands

# Snapshot current state (for debugging)
orca snapshot

# Trigger UI interaction programmatically
orca click

# Open Orca UI focused on worktree
orca open "task-name"

Scripting Example

Tạo 5 worktrees với cùng prompt để so sánh outputs:

#!/bin/bash
PROMPT="Refactor the authentication middleware to use async/await"
AGENTS=("claude-code" "codex" "gemini" "copilot" "opencode")

for i in "${!AGENTS[@]}"; do
  orca worktree create --name "refactor-$i" --agent "${AGENTS[$i]}"
  orca agent send "refactor-$i" "$PROMPT"
done

echo "All agents started. Use 'orca worktree list' to monitor."

Quy trình Single Agent — Một agent

Quy trình cơ bản nhất — 1 agent, 1 tác vụ (task), 1 worktree.

Khi nào dùng Single Agent

  • Tác vụ rõ ràng (Well-specified tasks) — Yêu cầu rõ ràng, chỉ có 1 cách đúng
  • Thay đổi máy móc (Mechanical changes) — Đổi tên, định dạng, thêm field, kết nối handler
  • Nhạy cảm chi phí (Cost-sensitive) — Tiết kiệm tokens
  • Giai đoạn học (Learning phase) — Bạn đang làm quen với Orca

Workflow chi tiết

1. Chuẩn bị prompt

Viết prompt rõ ràng với context đủ:

# BAD - vague
Fix the login bug

# GOOD - specific
Fix the login bug where users get "Invalid credentials" error even with
correct password.

Context:
- Issue affects users with email containing "+" character
- Auth logic is in src/auth/login.ts
- Test case to verify: user+test@example.com with password "Test123!"

Expected: Login succeeds
Actual: Always returns "Invalid credentials"

2. Create worktree và run

  1. New Worktree → Name: fix-plus-sign-login
  2. Agent: Claude Code (hoặc agent bạn prefer)
  3. Paste prompt và Enter

3. Monitor progress

Agent sẽ:

  • Read relevant files (src/auth/login.ts, related tests)
  • Analyze issue
  • Propose fix
  • Apply changes
  • Run tests (nếu configured)

4. Review và iterate

  • Diff View → Review changes
  • Nếu cần sửa: Annotate trên diff hoặc send follow-up prompt
  • Repeat cho đến khi satisfied

5. Merge

  • Commit changes trong worktree
  • Merge to main (hoặc create PR)
  • Delete worktree

Quy trình Parallel Agents — Nhiều agents song song

Phân tán (Fan-out) cùng một prompt cho nhiều agents, so sánh kết quả đầu ra (outputs), gộp (merge) bản thắng cuộc (winner).

Khi nào dùng Parallel

  • Vấn đề mơ hồ (Ambiguous problems) — Nhiều giải pháp (solutions) đều có thể đúng
  • Khám phá (Exploration) — Muốn xem nhiều cách tiếp cận (approaches) trước khi chọn
  • So sánh giữa các model (Cross-model comparison) — So sánh Claude vs Codex vs Gemini
  • Thay đổi quan trọng (High-stakes changes) — Muốn độ tin cậy cao (confidence) trước khi merge

Workflow chi tiết

1. Viết tiêu chí chấp nhận (acceptance criteria) TRƯỚC

Đây là bước quan trọng nhất. Không có tiêu chí, bạn sẽ không biết diff nào "đúng".

## Acceptance Criteria for Auth Refactor

1. All existing tests pass
2. New async/await syntax throughout (no .then() chains)
3. Error handling preserved - same error messages for same conditions
4. No new dependencies added
5. Performance: login time <= 200ms (current baseline: 180ms)
6. Type safety: no `any` types introduced

2. Create multiple worktrees

# Option A: Cùng một agent, nhiều runs
orca worktree create --name "refactor-a" --agent "claude-code"
orca worktree create --name "refactor-b" --agent "claude-code"
orca worktree create --name "refactor-c" --agent "claude-code"

# Option B: Nhiều agents khác nhau
orca worktree create --name "refactor-claude" --agent "claude-code"
orca worktree create --name "refactor-codex" --agent "codex"
orca worktree create --name "refactor-gemini" --agent "gemini"

3. Fan-out prompt

Gửi cùng prompt cho tất cả worktrees:

Refactor the authentication middleware to use async/await instead of
promise chains.

Requirements:
- Convert all .then()/.catch() to async/await
- Maintain existing error handling behavior
- Keep same function signatures for backward compatibility
- Add proper TypeScript types where missing

Start with src/middleware/auth.ts

4. Wait và monitor

  • Split terminal view để xem tất cả agents cùng lúc
  • Agents work independently trong isolated worktrees
  • Token consumption = N × single agent cost

5. Compare outputs

Khi tất cả agents hoàn thành:

  1. Mở Diff View cho từng worktree
  2. Check against acceptance criteria
  3. Run tests trong mỗi worktree: npm test
  4. Note: Không pick "cleanest-looking" diff — pick diff passes all criteria

6. Merge winner, delete losers

# Worktree refactor-claude passes all criteria
orca worktree merge refactor-claude

# Delete others
orca worktree delete refactor-codex
orca worktree delete refactor-gemini

Cost consideration

AgentsToken multiplierWhen worth it
11×Clear requirements, low risk
33×Medium ambiguity, want to compare
55×High stakes, need confidence
Rule: Viết criteria trước khi fan-out Nếu bạn không thể viết acceptance criteria, task chưa đủ rõ ràng để fan-out. Clarify requirements trước, fan-out sau.

Khi nào nên Phân tán (Fan-out)

Phân tán (Fan-out) hiệu quả khi:

Tình huống (Scenario)Tại sao fan-out giúp ích

Ví dụ thực tế

Ví dụ 1: Memory Leak Fix (Parallel approach)

Situation: React component có memory leak trong useEffect, không rõ nguyên nhân.

Setup:

  • 2 worktrees: Claude Code và Codex
  • Cùng prompt: "Fix memory leak in UserDashboard component"

Results:

  • Claude Code: Found timer leak, added cleanup handler for setInterval
  • Codex: Found setTimeout issues + suggested useRef optimization

Action: Merged both approaches — Claude's cleanup + Codex's useRef optimization. Result better than either alone.

Ví dụ 2: API Endpoint (Single agent)

Situation: Add new REST endpoint để get user preferences.

Why single:

  • Well-defined: GET /api/users/:id/preferences
  • Pattern exists: Other endpoints in codebase follow same structure
  • Low risk: Read-only operation

Result: Claude Code completed in 1 iteration, following existing patterns.

Ví dụ 3: Design Mode for Frontend (Single agent + Design Mode)

Situation: Button hover state looks wrong, need to match design specs.

Workflow:

  1. Open Design Mode → Navigate to page with button
  2. Click button → Send to agent với instruction: "Hover state should be #2563eb with 0.1s transition"
  3. Agent updates CSS
  4. Browser auto-refreshes → Verify change
  5. One small annotation: "Also add focus state for accessibility"
  6. Done in 2 iterations

Xác minh (Verification) — Khoảng trống quan trọng

Phân tán (Fan-out) nhân lên kết quả đầu ra nhưng không nhân lên khả năng ra quyết định. 5 agents tạo ra 5 diffs — đọc kỹ tất cả tốn nhiều thời gian hơn tự viết code.

Lỗi phổ biến (Common failure) Chọn diff "trông sạch nhất (cleanest-looking)" thay vì diff đúng nhất. Chạy song song (Parallelism) không giúp bạn đưa ra quyết định tốt hơn — nó chỉ cho bạn nhiều lựa chọn (options) hơn.

Chiến lược xác minh (Verification strategies)

1. Automated tests làm referee

# Chạy tests trong mỗi worktree
for wt in refactor-{a,b,c}; do
  cd .orca/worktrees/$wt
  npm test && echo "$wt: PASS" || echo "$wt: FAIL"
done

2. OpenAPI specs làm shared truth

Nếu có API specs, agents đọc cùng contract thay vì mỗi agent guess khác nhau.

3. Contract tests xác định winner

Chạy contract tests against tất cả worktrees — winner là worktree passes all contracts.

4. Metrics-based comparison

# So sánh bundle size
for wt in refactor-{a,b,c}; do
  cd .orca/worktrees/$wt
  npm run build
  du -sh dist/
done

Tối ưu chi phí (Cost Optimization)

Thực tế tiêu thụ token (Token consumption reality)

ScenarioTokens (approx)Cost
1 agent, simple task~10K$0.03-0.10
1 agent, complex task~50K$0.15-0.50
5 agents parallel, complex~250K$0.75-2.50

Chiến lược tối ưu hóa (Optimization strategies)

  1. Tối ưu single agent trước khi mở rộng (scale) — Nếu prompt của bạn lãng phí tokens với 1 agent, nó lãng phí 5× với 5 agents
  2. Dùng ghi chú trên diff (diff annotations) — Phản hồi trên dòng cụ thể (specific lines) tiết kiệm hơn nhắc lại toàn bộ (re-prompting)
  3. Phân tán (Fan-out) chỉ khi cần thiết — Tác vụ máy móc (Mechanical tasks) không cần 5 ý kiến
  4. Dùng agents miễn phí/rẻ hơn cho khám phá (exploration) — Hermes (miễn phí) cho khám phá ban đầu, Claude cho triển khai cuối (final implementation)

Xử lý sự cố (Troubleshooting)

Orca không phát hiện (detect) agent

Triệu chứng: Agent không xuất hiện trong danh sách

Cách sửa:

  1. Xác minh agent CLI hoạt động: claude --version, codex --version
  2. Khởi động lại (Restart) Orca để phát hiện lại
  3. Kiểm tra biến môi trường PATH (PATH environment variable)

Tạo worktree thất bại

Triệu chứng: "Failed to create worktree"

Cách sửa:

  1. Kiểm tra dung lượng đĩa (disk space): mỗi worktree cần không gian cho dependencies
  2. Kiểm tra phiên bản git: cần Git 2.20+
  3. Xác minh không có thay đổi chưa commit (uncommitted changes) trong worktree chính

Agent chậm hoặc treo (hang)

Triệu chứng: Agent không phản hồi (respond)

Cách sửa:

  1. Kiểm tra sử dụng RAM — đóng các worktrees không dùng
  2. Kiểm tra mạng (network) — các lệnh gọi API cần internet
  3. Kiểm tra hạn mức API (API quota) — có thể bị giới hạn tốc độ (rate limited)

Trình duyệt Design Mode không tải

Triệu chứng: Màn hình trắng trong Design Mode

Cách sửa:

  1. Xác minh dev server đang chạy trong worktree
  2. Kiểm tra cổng (port) — Orca mặc định localhost:3000
  3. Thử nhập URL thủ công trong Design Mode

Các lựa chọn thay thế (Alternatives)

Orca vs tmux + git worktree

Nếu bạn thích dùng thuần CLI (giao diện dòng lệnh):

# Cách thủ công với tmux + git worktree
git worktree add ../feature-a feature-a
git worktree add ../feature-b feature-b
tmux new-session -d -s agents
tmux split-window -h
# ... quản lý thủ công

Đánh đổi (Trade-off): Không có giao diện đồ họa (GUI), Design Mode, ghi chú diff (diff annotation), ứng dụng di động. Nhưng không tốn tài nguyên (zero overhead).
