AI-DLC Workflows

Framework chuẩn hóa AI coding assistant thành quy trình phát triển có kiểm chứng

Nguồn: awslabs/aidlc-workflows — MIT-0 License, AWS Labs
Tư duy cốt lõi AI-DLC = AI-Driven Development Life Cycle. Không phải "AI Development" — mà là dùng AI như một engine có quy trình, thay vì hỏi-trả lời ad-hoc. Framework duy trì traceability xuyên suốt: requirements → decisions → implementation → tests → operations.

Vấn đề AI-DLC giải quyết

Khi project scale lên, cách dùng AI coding kiểu "hỏi-trả lời" gặp các vấn đề:

  • Mất context — AI không nhớ các quyết định trước đó qua nhiều session
  • Không traceable — Không có audit trail, khó biết ai quyết định gì và tại sao
  • Thiếu cấu trúc — Không có workflow rõ ràng, dễ bỏ sót các bước quan trọng
  • Khó kiểm soát — AI tự do hành động, con người khó can thiệp đúng lúc

5 Phases — 33 Stages

AI-DLC chia vòng đời phát triển thành 5 giai đoạn tuần tự, mỗi giai đoạn có approval gate:

Initialization → Ideation → Inception → Construction → Operation
0Initialization

3 stages (0.1–0.3) — Thiết lập project context, xác định scope ban đầu, chuẩn bị môi trường

1Ideation

7 stages (1.1–1.7) — Thu thập requirements, phân tích user needs, định hình giải pháp

2Inception

9 stages (2.1–2.9) — Thiết kế architecture, technical decisions, planning chi tiết

3Construction

7 stages (3.1–3.7) — Implementation, testing, code review, integration

4Operation

7 stages (4.1–4.7) — Deployment, monitoring, maintenance, continuous improvement

Thiết lập

Cài đặt

aidlc config --harness claude
aidlc doctor

Lệnh aidlc doctor kiểm tra và báo cáo trạng thái cấu hình.

Harnesses được hỗ trợ

  • Claude Code — --harness claude
  • Kiro CLI — --harness kiro
  • Cursor — --harness cursor
  • GitHub Copilot — --harness copilot

Cách sử dụng

Với Claude Code

/aidlc Build a REST API for inventory management

Workflow cơ bản

  1. Mở Claude Code trong project directory
  2. Gõ /aidlc + mô tả task
  3. AI-DLC phân tích và chọn workflow profile
  4. Tiến qua từng phase, dừng tại approval gates
  5. Review và approve để tiếp tục
Approval Gates AI không thể tự vượt qua gate — phải có human approval. Đây là điểm kiểm soát quan trọng để đảm bảo chất lượng và phù hợp với yêu cầu thực tế.

Best Practices

Model Recommendation

Sử dụng model có reasoning mạnh để tận dụng tối đa AI-DLC. Claude Opus được khuyến nghị cho các task phức tạp.

Quy tắc quan trọng

  • Luôn review output — AI có thể mắc lỗi, cần human verification
  • Không bypass approval gates — Đây là điểm kiểm soát thiết yếu
  • Monitor cost — Theo dõi chi phí khi dùng AI agents
  • Leverage audit trail — Dùng log 99 events để debug và cải thiện
