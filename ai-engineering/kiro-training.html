Kiro Training Guide

Tài liệu đào tạo sử dụng Kiro IDE — từ ý tưởng đến phần mềm có kiểm soát

Nguồn: kiro.dev — AWS, 2025
Tư duy cốt lõi SDLC là luật chơi. Vibe, Spec, AI-DLC là cách làm việc với AI. Mọi cách dùng AI đều phải nằm trong SDLC và chính sách nội bộ — AI không thay thế quy trình, AI hỗ trợ bạn trong quy trình.

Kiro là IDE được hỗ trợ bởi AI, ra mắt bởi AWS giữa năm 2025. Không chỉ gợi ý code như Copilot, Kiro có thể đọc và hiểu toàn bộ project, lên kế hoạch trước khi làm, thực hiện nhiều bước liên tiếp, và dừng lại hỏi bạn khi không chắc chắn.

Vibe Mode — Việc Nhỏ/Cục Bộ

VIBE Prompt → Kiro đề xuất → Review → Accept/Reject → Done

Không có approval gates — bạn review trực tiếp trong chat. Dùng khi: một module, ít file, không đổi quy tắc nghiệp vụ, dễ quay lại.

Kiro Spec — Feature Vừa

SPEC Requirements → Design → Tasks → Execute

Có approval gates giữa mỗi phase. Dùng khi: có quy tắc/API/data model, cần BA–Dev–QA thống nhất, cần tài liệu để trace.

EARS Format — Viết Requirements Testable

WHEN [condition/trigger]
THE SYSTEM SHALL [behavior]

Ví dụ:

WHEN yêu cầu giao dịch có cùng idempotency key được gửi lại,
THE SYSTEM SHALL trả về kết quả ban đầu và không ghi nợ lần hai.
TránhThay bằng
"Nhanh""Trong 2 giây"
"Thân thiện""Hiển thị message X khi Y"
"An toàn""Encrypt với AES-256"

Context Engineering — Công Thức OCCE

Prompt tốt chưa đủ. Context đúng mới tạo khác biệt. Hãy giao việc như một hợp đồng kỹ thuật nhỏ, không phải một lời ước.
OOutcome
Kết quả gì?
CContext
Dựa vào đâu?
CConstraints
Không được gì?
EEvidence
Chứng minh sao?

Context Providers

ProviderCú phápMục đích
File#File:path/to/file.javaPhạm vi code cụ thể
Folder#Folder:src/servicesCả thư mục
Problems#problemsDiagnostics hiện tại
Terminal#terminalOutput và command gần đây
Git Diff#git diffThay đổi chưa commit
Spec#spec:feature-nameInclude full spec context

Ví dụ Prompt OCCE

#terminal #File:PaymentLimitServiceTest.java

[Outcome]
Phân tích và sửa lỗi để PaymentLimitServiceTest pass.

[Context]
Dựa trên lỗi trong terminal và file test.

[Constraints]
Trước khi sửa, tóm tắt nguyên nhân và kế hoạch.
Chỉ sửa service/file test liên quan.
Không đổi dependency hoặc config.

[Evidence]
Chạy test mục tiêu. Báo kết quả, file đã đổi,
diff chính và rủi ro còn lại.

MCP & Permissions

MCP (Model Context Protocol) cho phép Kiro kết nối với external servers để access tools, prompts, và resources.

Mỗi tool mới là một trust boundary mới stdio servers chạy với quyền process, có thể access code, env vars, và gửi data ra ngoài. Chỉ cấp khi thực sự cần.

Permission Model

EffectBehavior
denyBlock always, không hỏi — deny wins
askPrompt user mỗi lần
allowProceed silently

Permission Scopes (từ cao xuống thấp)

Kiro → Administration → User → Workspace → Agent → Session

rules:
  # Allow common git commands
  - capability: shell
    match: ["git status", "git log *", "git diff *"]
    effect: allow

  # Block writes to sensitive files
  - capability: fs_write
    match: ["*.env", "*.key", "*.pem", "secrets/*"]
    effect: deny

7 Lớp Guardrails — Defense in Depth

AI đề xuất. Người có thẩm quyền quyết định.
7. AUDIT — Logging, retention, incident path
6. VALIDATION — Test, SAST, CI, policy gates
5. REVIEW — Diff, owners, four-eyes
4. WORKSPACE — Branch/container, không production
3. PERMISSIONS — Deny > ask > allow; least privilege
2. IDENTITY — Tài khoản riêng; credential ngắn hạn
1. DATA — Không PII/secrets; mock; .kiroignore
Supervised Mode Không Phải Sandbox Supervised là workflow review, KHÔNG PHẢI security boundary. Cần nhiều lớp: Supervised + Permissions + CI + Branch protection.

Red Flags — Dừng Ngay

SignalAction
Real PII xuất hiệnSTOP, remove, report
Production endpointSTOP, verify scope
Secrets in codeSTOP, rotate immediately
Permission escalationSTOP, review with security

Checklist Trước Khi Execute

Business & Data

  • Scope/out-of-scope rõ ràng
  • PII và data classification xác định
  • Audit trail, retention policy
  • Owner phê duyệt requirements

Engineering & Operations

  • Idempotency, timeout, retry defined
  • Threat model và permissions
  • Rollback/feature flag strategy
  • Test strategy và observability
