Tailscale

Zero trust mesh network xây trên WireGuard — kết nối mọi thiết bị, mọi nơi, không cần cấu hình phức tạp

Nguồn: tailscale.com — Zero trust networking platform

Tailscale là nền tảng kết nối zero trust dựa trên WireGuard. Nó tạo ra một overlay mesh network kết nối thiết bị từ xa, multi-cloud, CI/CD runners, IoT và AI workloads — không cần bastion host, không cần cấu hình phức tạp.

Tư duy cốt lõi

3 nguyên tắc nền tảng 1. Identity-based, không location-based — xác thực bằng danh tính, không phải vị trí mạng
2. Mesh thay vì hub-and-spoke — peer-to-peer trực tiếp, không qua gateway trung tâm
3. Secure by default — deny-by-default, phải explicit cho phép qua ACLs

1. Identity-based Zero Trust

VPN truyền thống bảo vệ theo vị trí: "nếu bạn ở trong mạng nội bộ, bạn được tin tưởng". Tailscale bảo vệ theo danh tính: "bạn là ai?" quyết định bạn được truy cập gì, bất kể bạn đang ở đâu trên thế giới.

2. Mesh Network Architecture

Thiết bị kết nối trực tiếp với nhau (peer-to-peer) thay vì qua server trung tâm:

Device A ↔ Device B ↔ Device C

Kết quả: latency thấp hơn nhiều, không có bottleneck tại gateway, và coordination server có thể down mà existing connections vẫn hoạt động.

3. Secure by Default

Mặc định mọi thứ đều bị chặn. Không có ACL rule = không kết nối được. Ngược với mô hình "castle-and-moat" nơi một khi vào được bên trong, bạn có quyền truy cập mọi thứ.

Kiến trúc: Control Plane vs Data Plane

Control Plane (Coordination Server)

Tailscale chạy một coordination server trung tâm (hosted tại Tailscale hoặc self-hosted qua Headscale). Vai trò duy nhất:

  • Phân phối WireGuard public keys giữa các nodes
  • Trao đổi thông tin endpoint (IP, port) để thiết lập kết nối
  • Lưu trữ và distribute ACL policies
  • Xác thực nodes qua Identity Provider
Quan trọng Coordination server KHÔNG BAO GIỜ thấy hoặc xử lý data packets. Nó chỉ giúp thiết bị thiết lập kết nối — sau đó traffic đi trực tiếp peer-to-peer qua WireGuard.

Data Plane

Sau khi có đủ keys và endpoint info, các nodes thiết lập WireGuard tunnels trực tiếp với nhau. Coordination server hoàn toàn out of the loop cho data traffic.

AspectVPN truyền thốngTailscale
Traffic flowHub-and-spoke qua gatewayMesh peer-to-peer
Gateway downMất toàn bộ kết nốiExisting connections vẫn hoạt động
LatencyCao (qua trung tâm)Thấp (direct path)

WireGuard Integration

WireGuard Primitives

Tailscale xây trên WireGuard — protocol VPN hiện đại với:

  • Curve25519 cho key exchange (ECDH)
  • ChaCha20-Poly1305 cho symmetric encryption
  • BLAKE2s cho hashing
  • Codebase ~4000 dòng code, dễ audit

Tailscale Extends WireGuard

WireGuard thuần túy yêu cầu cấu hình tĩnh (static IP, static endpoints) — không phù hợp với internet động. Tailscale thêm:

  • Dynamic endpoint discovery — qua coordination server
  • Automatic re-keying — khi endpoint thay đổi
  • NAT traversal — reach peers sau NAT
  • ACL enforcement — access control trên top của WireGuard tunnels
  • Identity management — gắn với SSO/OIDC

Kernel vs Userspace

  • Linux: có thể dùng kernel WireGuard module (hiệu năng tốt nhất)
  • macOS, Windows, iOS, Android: dùng userspace implementation (wireguard-go)

NAT Traversal

Vấn đề

Phần lớn devices nằm sau NAT (router nhà, corporate firewall). Hai peers cùng nằm sau NAT khác nhau không thể kết nối trực tiếp theo cách thông thường.

STUN-like Direct Connection (Hole Punching)

  1. Mỗi node gửi UDP packets ra ngoài qua NAT
  2. NAT router tạo mapping: (internal IP:port) ↔ (external IP:port)
  3. Node A và B đều báo cáo external endpoint lên coordination server
  4. Coordination server trao đổi endpoint info
  5. A và B cùng gửi UDP packets đến external endpoint của nhau đồng thời
  6. NAT mapping được tạo theo cả hai chiều → direct UDP path thiết lập

Các loại NAT

NAT TypeHole Punching
Full ConeLuôn hoạt động
Restricted ConeHoạt động tốt
Port-Restricted ConeHoạt động tốt
SymmetricThường fail → dùng DERP

DERP Relay (Fallback)

Khi direct connection không thể thiết lập (đặc biệt với Symmetric NAT):

  • Tailscale chạy mạng lưới DERP relay servers phân tán toàn cầu
  • DERP servers chỉ là relay — không thể decrypt traffic vì data vẫn WireGuard-encrypted end-to-end
  • Node chọn DERP server gần nhất (low latency) làm relay
  • Tailscale tiếp tục cố gắng upgrade lên direct connection (background probing)
Ưu tiên connection 1. Direct peer-to-peer (tốt nhất)
2. Qua DERP relay (fallback)
3. Không bao giờ qua coordination server

Key Exchange & Authentication

Machine Keys

  • Được tạo khi cài đặt Tailscale client
  • Curve25519 private key, không bao giờ rời khỏi thiết bị
  • Dùng ECDH với NaCl crypto_box để chứng minh với coordination server

Node Keys

  • Được tạo riêng biệt khi user đăng nhập
  • Gắn với cả machine key và user identity (từ SSO)
  • Được distribute đến tất cả authorized peers trong tailnet

Authentication Flow

Device khởi động → Generate keypair → Auth qua SSO → Register với Coordination → Download peer keys

Key Distribution

  • Clients duy trì long-poll HTTPS connection để nhận updates nhanh
  • Key authorization và deauthorization gần như tức thì trên toàn network
  • Network map chỉ chứa thông tin scoped — chỉ các machines mà user được phép giao tiếp

Security Model: Zero Trust

Nguyên tắc cốt lõi

  • Private keys không bao giờ rời khỏi thiết bị
  • Coordination server chỉ thu thập và trao đổi public keys
  • Tailscale không thể đọc traffic của bạn — kể cả DERP relay servers
  • ACLs được locally enforced trên từng device

Tailnet Lock (Advanced)

Cho phép kiểm soát node nào được signed và verified bởi các trusted nodes trong tailnet — không cần tin tưởng coordination server để phân phối public keys.

Threat Model — Tailscale bảo vệ khỏi

Key Management

Key Rotation

  • Tự động và thủ công đều được hỗ trợ
  • Client có thể regenerate node keys và thay thế key cũ
  • Control server có thể yêu cầu regeneration định kỳ

Pre-Authorization

  • Network có thể yêu cầu machine authorization trước khi cho phép join
  • Pre-auth keys cho headless setup (servers, containers) — không cần interactive login

Revocation

  • Revoke ngay lập tức khi key bị rotate hoặc disabled thủ công
  • Existing connections bị terminate trong vài giây

Encryption

Data in transit (Tailscale traffic)WireGuard (ChaCha20-Poly1305)

Data at rest (Tailscale metadata)256-bit AES
Key negotiationCurve25519 ECDH via TLS

Compliance & Authentication

SSO Integration

Tailscale ủy quyền hoàn toàn cho identity provider của tổ chức:

  • Google, Microsoft AD, GitHub, Okta, OneLogin
  • SAML, OAuth2, OIDC
  • Mọi cài đặt authentication từ IdP được áp dụng tự động (MFA, context-aware access)

Compliance Certifications

  • SOC 2 Type II — Security, availability, confidentiality
  • PCI — Ủy quyền cho Stripe, đã hoàn thành SAQ A
  • Data Processing Addendum (DPA) cho tất cả customers

Audit Logging

  • Operations trong production được logged và audited
  • Coordination server logs không thể bị users giới hạn
  • DERP relay servers không log data (code open-source để verify)

ACLs (Access Control Lists)

Nguyên tắc

  • Deny-by-default: Không có rule = không kết nối được
  • Directional: Cho phép A→B không tự động cho B→A
  • Locally enforced: Rules chạy trên từng device
  • Format: HuJSON (JSON + trailing commas + comments)

ACL Rule Syntax

{
  "acls": [
    {
      "action": "accept",
      "src": ["group:engineering"],
      "proto": "tcp",
      "dst": ["tag:webserver:443"]
    }
  ]
}

MagicDNS

Tự động gán DNS name cho mọi device trong tailnet — không cần nhớ IP.

Naming Structure

{machine-name}.{tailnet-name}.ts.net

# Ví dụ
monitoring.yak-bebop.ts.net

Với search domains được cấu hình, chỉ cần gõ ping monitoring là resolve được.

Cấu hình

  • Mặc định bật với tailnets tạo sau 20/10/2022
  • Bật/tắt toàn mạng: Admin console → DNS page
  • Tắt theo device: tailscale set --accept-dns=false

Subnet Routers

Gateway device cho phép devices không cài Tailscale được truy cập qua tailnet. Dùng cho legacy devices, cloud VPCs, toàn bộ mạng nội bộ.

Setup (Linux)

# 1. Enable IP forwarding
echo 'net.ipv4.ip_forward = 1' | sudo tee -a /etc/sysctl.d/99-tailscale.conf
sudo sysctl -p /etc/sysctl.d/99-tailscale.conf

# 2. Advertise routes
tailscale set --advertise-routes=192.0.2.0/24,198.51.100.0/24

# 3. Approve qua admin console (hoặc dùng autoApprovers)

# 4. Client cần accept routes (Linux)
sudo tailscale set --accept-routes

Auto Approvers

"autoApprovers": {
  "routes": {
    "192.0.2.0/24": ["group:engineering", "tag:foo"]
  },
  "exitNode": ["tag:bar"]
}

High Availability

Nhiều subnet routers cùng advertise route → failover tự động.

Exit Nodes

Hoạt động như VPN truyền thống — toàn bộ internet traffic (non-Tailscale) đi qua device được chỉ định.

Khi nào dùng

  • Public Wi-Fi không tin tưởng (café, sân bay)
  • Truy cập nội dung bị geo-restrict
  • Compliance yêu cầu dùng VPN
  • Testing: simulate traffic từ location khác

Setup

# Trên exit node (Linux)
sudo tailscale set --advertise-exit-node

# Approve qua admin console

# ACL: PHẢI có grant với autogroup:internet
"grants": [
  {
    "src": ["group:remote-workers"],
    "dst": ["autogroup:internet"],
    "ip": ["*:*"]
  }
]

# Trên client
tailscale set --exit-node=<hostname-or-ip>

# Giữ truy cập LAN khi đang dùng exit node
tailscale set --exit-node-allow-lan-access
Sai lầm phổ biến Dùng exit node device IP làm dst trong ACL → chỉ permit SSH tới device đó, KHÔNG permit dùng làm internet gateway. Phải dùng autogroup:internet.

Tailscale SSH

Loại bỏ SSH key management. Thay vì distribute public keys, authentication dùng WireGuard node keys + centralized policy.

So với SSH truyền thống

SSH truyền thốngTailscale SSH
AuthenticationPublic/private key pairsWireGuard node keys (tự động)
Key distributionManual, phức tạpTự động qua Tailscale
Key expiryKhông expireExpire sau session
Access revocationPhức tạpTức thì (seconds)
Host verification~/.ssh/known_hostsTự động qua control plane

Setup

# Server (Linux/macOS)
tailscale set --ssh

# SSH policy
"ssh": [
  {
    "action": "check",
    "src": ["autogroup:member"],
    "dst": ["tag:production"],
    "users": ["autogroup:nonroot"],
    "checkPeriod": "8h"
  }
]

SSH Rule Modes

  • "accept": Tự động authenticate, không cần re-auth
  • "check": Yêu cầu re-auth qua identity provider

Connecting

# Bằng MagicDNS name
ssh device-name

# Với username
ssh ubuntu@device-name

# Bằng Tailscale IP
ssh user@100.64.0.1

Funnel & Serve

Tailscale ServeTailscale Funnel
ScopeChỉ trong tailnetPublic internet + tailnet
Ai truy cậpTeam membersBất kỳ ai
Use caseInternal sharingExpose service ra ngoài

Usage

# Serve (chỉ tailnet)
tailscale serve 3000

# Funnel (public internet)
tailscale funnel 3000

Funnel Requirements

  • Tailscale v1.38.3+
  • MagicDNS enabled
  • Valid HTTPS certificates (tự động provision)
  • Node attribute funnel trong policy file
  • Ports được hỗ trợ: 443, 8443, 10000
"nodeAttrs": [
  {
    "target": ["autogroup:member"],
    "attr": ["funnel"]
  }
]

Use Cases phổ biến

1. Business VPN

Truy cập từ xa cho toàn bộ team. Không cần VPN gateway tập trung, không cần quản lý certificates phức tạp.

2. Infrastructure Access

Kết nối trực tiếp tới Kubernetes cluster, database, internal services. Không cần bastion/jump host.

# SSH trực tiếp vào server trong tailnet
ssh user@prod-db.tailnet.ts.net

# kubectl qua tailnet
kubectl --server=https://k8s.tailnet.ts.net:6443 get pods

3. CI/CD Connectivity

Kết nối CI runners qua nhiều cloud provider. GitHub Actions runner ở AWS có thể truy cập database ở GCP qua tailnet.

4. Cloud VPC Access

Dùng subnet router để kết nối tới RDS, Cloud SQL, hoặc các resources trong private VPC mà không expose ra internet.

5. Homelab

Kết nối máy chủ cá nhân an toàn. Truy cập NAS, media server, home automation từ bất kỳ đâu.
